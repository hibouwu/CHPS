## Exercice I: Read-copy-update (17 points)

In this exercise, we will design a synchronization mechanism called **read-copy-update** (RCU). RCU allows readers to access a data structure without locks, even when threads are concurrently reading and updating the data. RCU decouples the deletion of an object into two phases:
1. A removal phase, where an object is removed from the data structure, and
2. A free phase, where the memory of the object is released.

While an object is removed, there may still be threads using it. RCU ensures that in the free phase for an object `o`, no threads are still using the removed object `o`. To achieve this, RCU provides a simple interface:

- `rcu_read_lock()`: signals that a thread is using the data structure. After calling `rcu_read_lock()`, another thread may remove the object from the data structure, but freeing the object is unsafe, as the thread may still use a pointer to the removed object.
- `rcu_read_unlock()`: signals that the thread is no longer using the data structure. After calling `rcu_read_unlock()`, the thread no longer has a pointer to the removed object.
- `rcu_synchronize()`: ensures that freeing the memory of a removed object is safe.

The following code illustrates the use of the RCU interface:

```c
struct object {
  const char* name;
};

struct object* obj;

void print_object() {
  rcu_read_lock();
  printf("%s\n", atomic_load(&obj)->name);
  rcu_read_unlock();
}

void update_object(const char* name) {
  struct object* old_object = atomic_load(&obj);
  struct object* new_object = malloc(sizeof(*new_object));
  new_object->name = name;
  atomic_store(&obj, new_object); // removes old_object
  rcu_synchronize(); // wait until no other thread holds a reference to old_object
  free(old_object);  // freeing old_object is now safe
}
```

To implement the RCU interface, we use these data structures and variables:

```c
struct thread {
  pthread_t tid;
  _Atomic bool is_reader;
};

_Thread_local struct thread* self; // my own struct thread
struct thread* all_threads; // an array with the struct thread of each thread
size_t nb_threads;
```

This structure describes a thread: `tid` gives the thread identifier, and `is_reader` indicates if the thread called `rcu_read_lock()` but not yet `rcu_read_unlock()`.

The algorithm works as follows:
- `rcu_read_lock()` sets the `is_reader` flag of the thread to `true`.
- `rcu_read_unlock()` sets it to `false`.
- `rcu_synchronize()` inspects each element of `all_threads`. For each thread `i`, `rcu_synchronize()` waits until `all_threads[i].is_reader` is `false`.

To illustrate why this implementation is correct, consider a thread T1 that deletes an object `obj`. First, T1 removes `obj` (e.g., the `atomic_store(&obj, new_object)` in the example). At this point, `obj` is not visible, but there may still be readers using `obj`. Then T1 calls `rcu_synchronize()`. If `rcu_synchronize()` observes that `all_threads[i].is_reader` is `false`, it means thread `i` is not a reader and does not hold a pointer to `obj`. Since `obj` is removed, we are sure that thread `i` will never get a pointer to `obj` again. Thus, after calling `rcu_synchronize()`, no threads hold a pointer to `obj`, and freeing it is safe.
