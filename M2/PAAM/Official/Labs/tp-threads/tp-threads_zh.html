线程与同步

练习 1：创建第一个线程程序

问题 1.a.

用 C 编写一个程序，通过 pthread_create 创建 N 个线程，其中 N 由程序的第一个参数给出。每个线程向终端输出 "[tid] Hello, World i!!!"，其中：

  • tid 是 pthread_self 返回的线程标识；
  • i 是 main 为每个线程依次分配的编号：第一个线程为 0，第二个为 1，依此类推。
补充答案与思路 · 1.a

先解析并检查参数 N，准备 N 个 pthread_t 来保存创建成功的线程标识，再调用 pthread_create 启动各线程。入口函数取得自己的编号 i，用 pthread_self() 取得当前线程标识，并输出题目要求的消息。

每个线程都要有独立、在读取期间仍有效的参数。 不要把循环变量 &i 反复传给所有线程：创建者还会修改它，新线程读取时编号可能已经改变。可为每个线程分配一份堆上的参数，在线程读完后释放；也可使用参数数组，但数组必须一直存活到所有使用者结束。如果主线程将调用 pthread_exit，不要让工作线程继续依赖主线程栈上的数组。

检查每次创建是否成功，后续只 join 已成功创建的线程。pthread_t 是线程标识类型，不保证在所有 POSIX 实现上都是可用同一个 printf 格式输出的整数。原站 hello.c 可作思路参考，但其中的 N 固定为 20；完成本题还需改为读取程序参数。

参阅：pthread_create。

问题 1.b.

现在让 main 在函数末尾输出 Main quitting。使用 3 个线程，多运行几次程序。为什么有时会先输出 Main quitting，再输出三个 Hello, World？

补充答案与思路 · 1.b

pthread_create 启动线程，但不会等它输出消息。创建者与新线程谁先运行，由调度（scheduling）决定；没有额外同步时，main 可以先执行到自己的输出语句。

因此，创建线程的先后顺序不能保证消息的输出顺序。要保证 Main quitting 在最后，必须先等待工作线程完成相应工作，例如使用后面题目中的 pthread_join；加一个固定时长的 sleep 并不能建立这种保证。

参阅：线程创建后的调度。

问题 1.c.

将线程数设为 20，多运行几次。为什么程序经常没有输出满 20 次 Hello, World？

补充答案与思路 · 1.c

从 main 返回会结束整个进程（process），仍在运行或尚未得到执行机会的工作线程也随之结束。主线程若很快走到函数末尾，一部分线程可能还没执行到 printf，所以看到的输出少于 20 行。

这不说明线程数量上限就是当前看到的行数。首先检查 20 次 pthread_create 是否都成功，再检查退出与等待方式。后面通过 pthread_exit 或 join 改变进程退出的时机。

参阅：main 返回与线程终止。

问题 1.d.

在 main 末尾增加一次 pthread_exit 调用。为什么现在以 20 个线程启动时，总能看到 20 次 Hello, World？

补充答案与思路 · 1.d

pthread_exit 只结束调用它的线程（thread）。主线程这样结束时，其他线程可以继续执行；最后一个线程结束后，进程才正常退出。因此，在 20 个线程都创建成功、参数有效且工作线程正常完成的前提下，它们都有机会输出自己的消息。

它不等于“主线程等待后继续执行”。 pthread_exit 不返回，所以不要把 Main quitting 放在它后面并期待被执行；它也不会把之前已经打印的 Main quitting 移到其他输出之后。

参阅：pthread_exit。

问题 1.e.

继续修改，使 Main quitting 一定在所有 Hello, World 都输出之后才出现。

补充答案与思路 · 1.e

先创建所有工作线程并保存它们的标识，再依次对每个成功创建的线程调用 pthread_join。所有 join 成功返回后，才输出 Main quitting。由于工作线程在返回前已经输出消息，这样就能保证主线程的这条输出位于最后。

不要在创建循环里每创建一个线程就立即 join 它，否则下一线程要等前一个结束后才会创建，实验几乎变成串行执行。join 的调用顺序不会指定工作线程之间的输出顺序，只保证全部完成以后 main 才继续。

此时所有工作线程都已结束，main 可以正常返回；不再需要靠 pthread_exit 维持进程存活。

参阅：pthread_join。

hello.c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>

#define N 20

void* hello(void* _arg) {
  int* p = _arg;
  printf("[%llx] Hello from %d\n", (unsigned long long)pthread_self(), *p);
  free(p);
  return NULL;
}

int main(int argc, char* argv[]) {
  pthread_t tid[N];
  void* retval;

  for(int i=0; i<N; i++) {
    int* p = malloc(sizeof(*p));
    *p = i;
    pthread_create(&tid[i], NULL, hello, p);
  }

  for(int i=0; i<N; i++)
    pthread_join(tid[i], &retval);

  printf("Quitting\n");
  
  pthread_exit(NULL);
  return 0;
}

练习 2：共享计数器

问题 2.a.

先增加一个名为 counter 的全局变量，初值为 0。每个线程在输出 Hello, World 后将它加一。最后，在 main 调用 pthread_exit 之前输出 counter 的值。

以 100 个线程运行时，为什么输出的计数器值经常小于 100？修改程序，使程序结束时计数器等于线程数。

补充答案与思路 · 2.a

需要区分两个问题。

  1. 读取过早。 如果 main 还没有等待工作线程完成，读取计数器时，一些递增可能尚未发生。若已完整保留 1.e 的 join，这个原因就已排除。
  2. 递增发生竞争。 普通整数上的 counter++ 不保证原子性。用读—改—写模型看，两个线程都读到 0，各自算出 1，再各写回 1，就丢失了一次更新（lost update）。严格按 C 语义，无同步的冲突访问还构成数据竞争（data race），导致未定义行为（undefined behavior），不能把所有运行结果限制为这个简单模型。

修正时，让所有递增在同一把互斥锁（mutex）保护下执行，并在主线程 join 全部工作线程以后读取最终值。读取时已经不存在并发写入；若还要在运行期间读取计数器，则这些读取也须遵守相同的同步规则。

也可以使用原子计数器及原子递增，但仍需要处理“什么时候读取”的问题。只加 join 不会修复工作线程之间的竞争，只加原子递增也不会等待所有线程完成。 正确同步后，在每个成功创建的线程恰好递增一次的前提下，最终值应等于线程数。

可对照：线程与同步讲义。

问题 2.b.

修改程序，使它只在计数器等于线程数时输出 "Main quitting"。
补充答案与思路 · 2.b

可以用计数器作为共享条件，让主线程通过条件变量（condition variable）等待它达到 N。

  • 工作线程先完成自己的 Hello, World 输出，再获取互斥锁，递增 counter；当它变成 N 时通知等待者，然后解锁。
  • main 获取同一把锁，用 while (counter < N) 检查谓词（predicate）；条件不满足就调用 pthread_cond_wait(&done, &mutex)。
  • wait 在等待期间释放锁，使工作线程可以递增；返回前重新取得锁。退出 while 后，才输出 Main quitting。

必须用 while 重查条件，以处理虚假唤醒（spurious wakeup）等情况。如果最后一次通知发生在 main 开始等待之前，计数器已经保存了完成状态，main 会直接跳过等待，因此不依赖条件变量保存过去的通知。

若要回收 joinable 线程资源，之后仍应 join 所有工作线程。counter == N 只说明各线程已完成递增之前的工作，不一定说明它们已经执行到入口函数的末尾。

参阅：条件等待与谓词检查。

练习 3：生产者与消费者

本练习实现生产者／消费者模型。主线程作为生产者，从标准输入逐行读取文本并放入队列；其他线程作为消费者，按 FIFO（先进先出）顺序从队列中取出这些行并输出。

使用链表实现队列：第一个节点保存最早入队的行，最后一个节点保存最新入队的行。为避免每次入队都遍历整个链表，需要同时保存指向第一个节点和最后一个节点的指针。

问题 3.a.

先实现单消费者的单播队列：只有一个消费者从队列取消息。队列为空时，消费者必须通过 pthread_cond_wait 休眠。节点被消费后，要记得释放其内存。
补充答案与思路 · 3.a

用头指针 head、尾指针 tail、一把 mutex 和一个条件变量管理队列。单播（unicast）意味着每条消息只由一个消费者取走，本题先只创建一个消费者。

生产者为每一行准备独立存储，在持锁时把新节点接到 tail 后面；原队列为空时，同时设置 head，再更新 tail 并通知消费者。消费者持锁检查队列，若为空便在 while 循环中调用 pthread_cond_wait；非空时摘下 head，如果队列因此变空，也要将 tail 置空。

摘下节点后，单消费者独占这个节点，便可解锁、输出消息，再释放消息和节点。不要让所有节点都指向同一个会被下一次输入覆盖的缓冲区。要满足“逐行读取”，可用 getline 或合适的 fgets 处理，而不是用按空白分词的 %s 输入。

可选完善：在同一把锁下维护 closed 标志。输入结束后设置 closed 并唤醒等待者；消费者只在“队列为空且输入已结束”时退出，否则继续排空队列。原站 spsc.c 用词输入和退出字符串演示同步，并不是完整的逐行输入与 EOF 处理程序。

spsc.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <pthread.h>
#include <stdint.h>

#define MAX_LENGTH 256
#define xstr(s) str(s)
#define str(s) #s

pthread_mutex_t mutex = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;

struct node {
  struct node* next;
  char msg[MAX_LENGTH];
};

struct node* head = NULL;
struct node* tail = NULL;

void* consumer(void* _arg) {
  int i = (int)(uintptr_t)_arg;

  for(;;) {
    pthread_mutex_lock(&mutex);
    while(head == NULL)
      pthread_cond_wait(&cond, &mutex);

    struct node* n = head;
    head = n->next;
    if(!head)
      tail = NULL;
    pthread_mutex_unlock(&mutex);

    printf("[%d] Receive: %s\n", i, n->msg);
    free(n);
  }

  return 0;
}

void producer() {
  for(;;) {
    struct node* cur = malloc(sizeof(*cur));

    scanf("%"xstr(MAX_LENGTH)"s", cur->msg);

    if(strncmp(cur->msg, "exit", MAX_LENGTH) == 0)
      exit(0);

    cur->next = NULL;
    
    pthread_mutex_lock(&mutex);
    if(tail)
      tail->next = cur;
    else
      head = cur;
    tail = cur;
    pthread_cond_signal(&cond);
    pthread_mutex_unlock(&mutex);
  }
}

int main(int argc, char** argv) {
  if(argc != 2) {
    fprintf(stderr, "Usage: %s nb-threads\n", argv[0]);
    exit(1);
  }

  int n = atoi(argv[1]);
  pthread_t tids[n];

  for(int i=0; i<n; i++)
    pthread_create(tids + i, NULL, consumer, (void*)(uintptr_t)i);

  producer();
  
  for(int i=0; i<n; i++) {
    void* retval;
    pthread_join(tids[i], &retval);
  }

  printf("Main quitting\n");
  
  return 0;
}

问题 3.b. 共享内存中的原子广播（选做，1/2）

将程序改成多播队列：每个消费者都必须按 FIFO 顺序接收并输出每一行。仍需正确释放链表节点。
补充答案与思路 · 3.b

广播（broadcast）要求每个消费者都收到每条消息。仅把 pthread_cond_signal 换成 pthread_cond_broadcast 不够：如果仍让第一个醒来的消费者摘掉 head，其他消费者就再也看不到这条消息。

一种容易理解的基础方案是让所有消费者围绕当前 head 同步推进。每个节点有序号和剩余消费者数 remaining，初值为固定的消费者总数 N；每个消费者记录自己上一次处理的序号，防止重复处理同一节点。

在同一把 mutex 下，消费者等待“head 存在且自己尚未处理它”，处理当前消息，再把 remaining 减一。为简化这一版本，可以在锁内完成输出。只有 remaining 变为 0 时，才摘下并释放 head、更新必要的 tail 状态，再广播唤醒各消费者处理下一节点。生产者加入消息时也要唤醒相关等待者。

这样每条消息恰好处理 N 次，每个消费者保持 FIFO 顺序；代价是快消费者需要等慢消费者。原子广播这里强调各消费者看到相同的消息顺序，不表示整个程序只需一条硬件原子指令。以下一题解除这种逐节点共同推进的限制。

问题 3.c. 共享内存中的原子广播（选做，2/2）

在广播版本上，尝试让各消费者独立向前处理，不必等其他消费者都处理完前一个节点。你的初始版本可能让所有消费者一起处理一个节点，然后才进入下一个；现在要解除这种同步推进的限制。每个消费者内部仍须遵守上一题要求的 FIFO 顺序。
补充答案与思路 · 3.c

给每个消费者一个独立游标（cursor），指向它的下一条未读消息，同时为节点维护剩余使用者计数（reference count）。快消费者处理完自己的当前消息后可以继续向后走，无需等待其他消费者；它不能跳过自己的旧消息，所以仍保持自身的 FIFO 顺序。

一种便于推理的实现仍用全局 mutex：生产者追加节点时，将该节点发布给所有已经到达链尾、正在等新消息的消费者；消费者在锁内复制当前消息、保存后继并前移自己的游标，再递减节点计数。解锁后用副本输出，输出完才处理自己的下一条消息。锁仅保护队列状态和游标操作，不要求所有消费者一起处理同一节点。

只有当所有消费者都越过节点，而且生产者和共享队列指针也不再需要它时，才可以摘链并释放；若它是最后一个节点，还要同步修正 tail。某个消费者已读完，不足以说明该节点可释放。实现也可使用哨兵节点，但同样必须明确最后一个节点与等待新消息的游标如何衔接。

原站参考代码有一处需要修正： mpmc.c 在 free(cons) 后还调用 pthread_mutex_unlock(&cons->mutex)，访问了已经释放的对象。不能按这个顺序照抄。正确释放需要先证明没有其他使用者，并完成解锁及必要的同步对象清理；简单移动一行 free 并不能替代这个生命期证明。

mpmc.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <pthread.h>
#include <stdint.h>
#include <stdbool.h>
#include <unistd.h>

#define MAX_LENGTH 256
#define xstr(s) str(s)
#define str(s) #s

struct node {
  char msg[MAX_LENGTH];
  struct node* next;
  size_t cpt;
  pthread_mutex_t mutex;
  pthread_cond_t cond;
};

struct thread_arg {
  struct node* fake;
  size_t id;
};

struct node* new_node(size_t n) {
  struct node* node = malloc(sizeof(*node));
  
  node->next = NULL;
  node->cpt = n;
  pthread_mutex_init(&node->mutex, NULL);
  pthread_cond_init(&node->cond, NULL);

  return node;
}

struct thread_arg* new_arg(size_t id, struct node* fake) {
  struct thread_arg* arg = malloc(sizeof(*arg));

  arg->fake = fake;
  arg->id = id;
  
  return arg;
}

void* consumer(void* _arg) {
  struct thread_arg* arg = _arg;
  struct node* cons = arg->fake;
  size_t id = arg->id;

  free(arg);

  for(;;) {
    bool was_free = false;
    
    pthread_mutex_lock(&cons->mutex);
    while(cons->next == NULL)
      pthread_cond_wait(&cons->cond, &cons->mutex);
    char buf[MAX_LENGTH];
    strncpy(buf, cons->msg, MAX_LENGTH);
    struct node* tmp = cons->next;
    if(--cons->cpt == 0) {
      was_free = true;
      free(cons);
    }
    pthread_mutex_unlock(&cons->mutex);

    cons = tmp;

    if(strncmp(buf, "exit", MAX_LENGTH) == 0) {
      printf("===== [%zu] exiting ======\n", id);
      pthread_exit(NULL);
    } else {
      printf("[%zu] receive: %s%s\n", id, buf, was_free ? " (free the node)" : "");
      // simulate different speeds, consummer i is faster than consummer i+1
      //usleep((id-1)*100000);
    }
  }
}

// here, the thread_arg is just here if we want to test with multiple producers
void producer(struct thread_arg* _arg) {
  struct thread_arg* arg = _arg;
  struct node* prod = arg->fake;
  size_t id = arg->id;

  free(arg);

  char* poeme[] =
    {
      "Avec", "ses", "quatre", "dromadaires",
      "Don", "Pedro", "d’Alfaroubeira",
      "courut", "le", "monde", "et", "l’admira",
      "il", "fit", "ce", "que", "je", "voudrais", "faire",
      "si", "j’avais", "quatre", "dromadaires",
      "exit"
    };
  size_t i = 0;
  
  for(;;) {
    //char msg[MAX_LENGTH];
    //scanf("%"xstr(MAX_LENGTH)"s", msg);
    char* msg = poeme[i++];
    
    struct node* next = new_node(prod->cpt);

    pthread_mutex_lock(&prod->mutex);
    printf("[%zu] produce: %s\n", id, msg);
    prod->next = next;
    strncpy(prod->msg, msg, MAX_LENGTH);
    pthread_cond_broadcast(&prod->cond);
    pthread_mutex_unlock(&prod->mutex);

    if(strncmp(msg, "exit", MAX_LENGTH) == 0)
      return;

    prod = next;
  }
}

int main(int argc, char** argv) {
  if(argc != 2) {
    fprintf(stderr, "Usage: %s nb-threads\n", argv[0]);
    exit(1);
  }

  int n = atoi(argv[1]);
  pthread_t tids[n];

  struct node* list = new_node(n);
  
  for(int i=0; i<n; i++)
    pthread_create(tids + i, NULL, consumer, new_arg(i + 1, list)); // 1...n are the consummers

  producer(new_arg(0, list)); // 0 is the producer
  
  for(int i=0; i<n; i++) {
    void* retval;
    pthread_join(tids[i], &retval);
  }

  printf("Main quitting\n");
  
  return 0;
