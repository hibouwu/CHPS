问题 6 · 选做：hazard pointers（较难）

为避免节点使用期间因重新分配而出现 ABA 风险，需要保证线程仍使用节点 A 时，A 不会被重新分配。这里采用 hazard pointers，参考 Maged Michael 的论文 “Hazard Pointers: Safe Memory Reclamation for Lock-Free Objects”，TPDS 2004。

线程从位置 L 读出指针 X，准备以 CAS 将 L 从 X 改为其他值时，需要保证从读取到 CAS 之间，X 所指节点不会被重新分配。为此，线程在使用 X 期间，将 X 登记在自己负责的 hazard 槽位中。只要某个 hazard 槽仍指向 X，算法就不能释放该节点。

对队列而言，dequeue 先从 head 读取 X，将 X 写入 hazard，然后重读 head；若 head 已不等于 X，就从头重试。CAS 成功后，先将本线程的 hazard 清为 0，再将 X 放入名为 free_nodes 的无锁栈，而不立即释放它。

enqueue 中修改 tail 时也要保护所用节点：先读取 tail，把值登记到本线程的 hazard，重读 tail 并确认它未改变；完成相应 CAS 后，再将 hazard 清为 0。

enqueue 需要节点时，应先尝试从 free_nodes 中取，再考虑用 malloc 分配。具体过程如下：

  • 以无锁方式从 free_nodes 栈弹出指针 Z；
  • 若 Z 为空，即栈中没有可用节点，则使用 malloc；
  • 若 Z 非空，则检查：
    • 如果其他线程的某个 hazard 槽仍保存 Z，说明节点仍在使用中。将 Z 重新压栈，并通过 malloc 分配新节点；
    • 否则，该节点已经空闲且无人使用，可直接复用以入队新值，无需调用 malloc。

一个简单的内存分配器

本练习实现内存分配器。分配器内部管理内存块（chunk），每个块代表一段处于空闲或已分配状态的内存。结构如下：

struct chunk {
  size_t size;
  union {
    struct chunk* next; /* next node when the chunk is free */
    char content[0];    /* the content of the chunk when allocated */
  };
};

对外提供两个函数：

  • struct chunk* alloc_chunk(size_t size)：分配大小为 size 的内存块；
  • void free_chunk(struct chunk* c)：释放内存块 c。

空闲块 c 保存在全局链表 struct chunk* free_list 中，c->next 指向下一个空闲块。块已分配时，它不在 free_list 中，next 字段也不再作为链使用，用户可在 c->content 保存对象内容。

分配时，alloc_chunk 在空闲链表中查找第一个足够大的块 c，并将它摘下。如果整块返回会浪费可分割的空间，则在原块的区域内构造另一个块，把大块拆成两部分。译注：这一段原文把链表写成 free_chunk，还使用了结构中不存在的 c->chunk 字段；下方保留原题给出的具体分割步骤，写实现前需统一 size 是否包含块头及对齐约定。

原题给出的 alloc_chunk 步骤为：
  • 在 free_list 中找到第一个满足 size < c->size 的块 c；
  • 将 c 从链表中摘下；
  • 如果 size + sizeof(struct chunk) < c->size，则：
    • 创建新块 struct chunk* d = (struct chunk*)((uintptr_t)c + size)；
    • 将 d->size 设为 c->size - size，再将 c->size 设为 size；
    • 释放块 d，使其回到空闲结构中；
    • 返回 c。
  • 否则，即 size + sizeof(struct chunk) >= c->size，直接返回整个 c。
