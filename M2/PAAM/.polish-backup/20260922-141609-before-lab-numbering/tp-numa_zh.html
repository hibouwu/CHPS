非均匀内存访问架构

测量 NUMA 内存访问

本练习尝试测量 NUMA 机器上的内存访问时间。

问题 1

首先连接测试机器 “arya”，连接方法请向教师询问。

问题 2

使用 lstopo-no-graphics 查看 NUMA 拓扑，找出 NUMA 节点数、每个节点的内存容量，以及每个节点包含的处理单元数（逻辑处理器数）。L1、L2、L3 缓存分别有多大？

问题 3

使用一个线程多次读取大缓冲区来测量访问时间，称它为测试线程。再加入其他线程产生内存流量，称它们为噪声线程，用于观察干扰下的性能。编写 C 程序，接收以下参数：
  • 第一个参数 test_pu：整数，指定测试线程运行的处理单元；
  • 第二个参数 test_node：整数，指定测试缓冲区所在的 NUMA 节点；
  • 第三个参数 test_buffer：测试缓冲区大小，单位为千字节，按题中 1024 字节计算；
  • 第四个参数 test_workload：测试线程总共访问的千字节数。例如 test_buffer=1、test_workload=2，表示完整遍历缓冲区两次；
  • 第五个参数 noisy_config：噪声线程配置，可取以下值：
    • none：不创建噪声线程；
    • spread：除测试线程使用的处理单元外，每个处理单元都运行一个噪声线程。线程访问位于 (n + 1) % number_of_nodes 节点的缓冲区，其中 n 是该线程所在的 NUMA 节点，number_of_nodes 为总节点数；
    • overload：线程安排与 spread 相同，但所有噪声缓冲区集中到指定节点，见下一个参数；
  • 第六个参数 noisy_node：整数，指定 overload 模式下噪声线程访问的 NUMA 节点。

当前阶段只需检查参数数量并解析这些参数值。

问题 4

接下来使用 hwloc 库读取 NUMA 拓扑，可复用下方代码。链接时加入 -lhwloc，正确运行后应能输出机器的 NUMA 拓扑。主要结构为 numa：其中包含 NUMA 节点数组和处理单元数组；每个处理单元关联一个节点，每个节点也保存自己的处理单元数组。

main.c
#include <hwloc.h>
#include <stdio.h>
#include <stdbool.h>

hwloc_topology_t topology;

struct node {
  hwloc_obj_t obj;
  struct pu* pus;
  size_t nb_pus;
};

struct pu {
  hwloc_obj_t obj;
  struct node* node;
};

struct topology {
  size_t nb_nodes;
  size_t nb_pus;
  struct pu* pus;
  struct node* nodes;
}* numa;

void print_obj(hwloc_obj_t obj, char* prefix, bool verbose) {
  char type[32];
  char attributes[256];
    
  // Récupérer le type de l'objet
  hwloc_obj_type_snprintf(type, sizeof(type), obj, 0);
    
  // Récupérer les attributs de l'objet
  hwloc_obj_attr_snprintf(attributes, sizeof(attributes), obj, " ", 0);
    
  // Afficher les informations de l'objet
  if(verbose) {
    printf("%sObject@%p\n", prefix, obj);
    printf("%s  Object Type: %s\n", prefix, type);
    printf("%s  OS Index: %d\n", prefix, obj->os_index);
    printf("%s  Attributes: %s\n", prefix, attributes);
    printf("%s  Depth: %d\n", prefix, obj->depth);
    printf("%s  Logical Index: %d\n", prefix, obj->logical_index);
    printf("%s  Number of Children: %u\n", prefix, obj->arity);
  } else
    printf("%s%s at index %d\n", prefix, type, obj->logical_index);
}

hwloc_obj_t is_ancestor(hwloc_obj_t base, hwloc_obj_t obj) {
  for(hwloc_obj_t cur=obj; cur; cur=cur->parent)
    if(cur == base)
      return cur;
  return NULL;
}

void extract_numa_topology() {
  // To understand the topology, you can take a look at the page here: https://www.open-mpi.org/projects/hwloc/doc/v2.2.0/a00325.php
  numa = malloc(sizeof(*numa));

  // allocate the space for the nodes
  int depth_numa = hwloc_get_type_depth(topology, HWLOC_OBJ_NUMANODE);

  numa->nb_nodes = hwloc_get_nbobjs_by_depth(topology, depth_numa);
  numa->nodes = malloc(sizeof(*numa->nodes)*numa->nb_nodes);
  
  // record the numa nodes
  hwloc_obj_t obj = NULL;
  size_t n = 0;
  while ((obj = hwloc_get_next_obj_by_type(topology, HWLOC_OBJ_NUMANODE, obj)) != NULL) {
    numa->nodes[n].obj = obj;
    numa->nodes[n].nb_pus = 0;
    n++;
  }
  
  // allocate the space for the cpus
  int depth_pu = hwloc_get_type_depth(topology, HWLOC_OBJ_PU);

  numa->nb_pus = hwloc_get_nbobjs_by_depth(topology, depth_pu);
  numa->pus = malloc(sizeof(*numa->pus)*numa->nb_pus);

  // record the cpus and associates them to the nodes
  obj = NULL;
  n = 0;
  while ((obj = hwloc_get_next_obj_by_type(topology, HWLOC_OBJ_PU, obj)) != NULL) {
    numa->pus[n].obj = obj;
    
    for(size_t i=0; i<numa->nb_nodes; i++)
      if(is_ancestor(numa->nodes[i].obj->parent, numa->pus[n].obj)) {
        numa->pus[n].node = &numa->nodes[i];
        numa->pus[n].node->nb_pus++;
      }
    
    n++;
  }

  // build the invert tree
  for(size_t i=0; i<numa->nb_nodes; i++) {
    numa->nodes[i].pus = malloc(sizeof(*numa->nodes[i].pus)*numa->nodes[i].nb_pus);
    numa->nodes[i].nb_pus = 0;
  }

  for(size_t i=0; i<numa->nb_pus; i++) {
    struct node* node = numa->pus[i].node;
    node->pus[node->nb_pus++] = numa->pus[i];
  }
}

void print_numa_topology() {
  for(size_t i=0; i<numa->nb_nodes; i++) {
    print_obj(numa->nodes[i].obj, "", 0);
    for(size_t j=0; j<numa->nodes[i].nb_pus; j++)
      print_obj(numa->nodes[i].pus[j].obj, "  ", 0);
  }
}

int main(int argc, char* argv[]) {
  // Initialize topology
  hwloc_topology_init(&topology);
  hwloc_topology_set_flags(topology, HWLOC_TOPOLOGY_FLAG_WHOLE_SYSTEM);
  hwloc_topology_load(topology);

  extract_numa_topology();
  print_numa_topology();

  hwloc_set_cpubind(topology, numa->pus[0].obj->cpuset, HWLOC_CPUBIND_THREAD);

  char* buf = hwloc_alloc_membind(topology,
                                  32 * 1024 * 1024,
                                  numa->pus[0].node->obj->nodeset,
                                  HWLOC_MEMBIND_BIND,
                                  HWLOC_MEMBIND_STRICT | HWLOC_MEMBIND_BYNODESET | HWLOC_MEMBIND_NOCPUBIND );

  printf("=> %p\n", buf);
  
  // cleanup
  hwloc_topology_destroy(topology);
  return 0;
};

问题 5

创建测试线程，将它绑定到 test_pu 指定的处理单元。在 numa->pus 中查找 numa->pus[i].obj->logical_index 等于 test_pu 的项。hwloc 的 hwloc_set_cpubind 可用于绑定当前线程，示例如下：

hwloc_set_cpubind(topology, numa->pus[0].obj->cpuset, HWLOC_CPUBIND_THREAD);
将示例中的下标 0 换成查找到的处理单元，即 logical_index 等于 test_pu 的那一项。

问题 6

若 noisy_config 为 spread 或 overload，就在除测试线程所在 PU 以外的各个 PU 上启动噪声线程。

问题 7

为噪声线程分配缓冲区。原题让每个噪声线程持续顺序访问 32MB 的缓冲区，并以该大小超出测试机器 L3 缓存为前提，从而产生到内存控制器的流量。缓冲区按下述方式放置：

  • spread 模式：放在噪声线程所在节点 N 的下一个节点 N+1；节点编号回绕按前面 (n + 1) % number_of_nodes 的定义处理；
  • overload 模式：放在 noisy_node 指定的节点。

从指定节点分配内存时，可参考下面代码：

  char* buf = hwloc_alloc_membind(topology,
                                  32 * 1024 * 1024,
                                  numa->pus[0].node->obj->nodeset,
                                  HWLOC_MEMBIND_BIND,
                                  HWLOC_MEMBIND_STRICT | HWLOC_MEMBIND_BYNODESET | HWLOC_MEMBIND_NOCPUBIND );
原题这里再次要求用 test_pu 的 logical_index 替换下标 0；但本题分配的是噪声缓冲区，应根据 spread／overload 配置选定目标节点的 nodeset，不要把它误固定到测试线程节点。

问题 8

让噪声线程不断访问各自 32MB 的缓冲区，因此此阶段程序暂时不会结束。每轮遍历中，每条缓存行只访问一次，避免反复读取同一行主要落在 L1。将缓冲区视为 struct cache_line 数组，结构如下：

struct cache_line {
  union {
    char _content[64]; // 64 bytes in each cache line
    int  value;
  };
};

噪声线程无限重复遍历，每轮读取 32 * 1024 * 1024 / sizeof(struct cache_line) 条缓存行的 value 字段。

若使用优化选项（-O2 或 -O3），没有可观察结果的读取循环可能被编译器删除。可先关闭优化，或让读取参与实际计算，例如将每条缓存行的 value 累加到变量 r，并在循环结束时把 r 写入适当的全局结果位置，避免连累加本身也被消去。译注：原题将 -O2 误写为 -02。若多个线程共享结果位置，还须正确同步。

问题 10

测量时以缓存行为访问单位，不逐字节读取。复用前面定义的 struct cache_line。

将测试缓冲区当作 cache_line 数组，每次读取一条缓存行的整数 value。题目按读取该行代表访问 64 字节计量；再读取同一行其他字节会给测量增加额外工作。因此，要访问 test_workload 千字节，需要读取 test_workload * 1024 / 64 条缓存行，将这个次数记为 num_access。

顺序执行 num_access 次缓存行读取，每次只读 value。当访问位置到达 test_buffer * 1024 / 64 条缓存行的末尾时，要回到缓冲区开头继续。

使用 clock_gettime 和 CLOCK_MONOTONIC 计时，将循环总耗时除以 num_access，报告每次缓存行访问的平均时间。

问题 11

顺序访问容易被处理器识别，触发提前预取，因此当前结果不能直接当作未预取条件下的内存访问延迟。

接下来改用随机位置访问，减弱顺序预取的影响。不要在测量循环中调用 rand()，否则随机数生成本身可能主导耗时。提前生成随机索引，存入缓冲区各缓存行的 value 字段。测量从 cur = 0 开始，每次读取当前位置保存的下一索引，再沿它访问；cache_lines 是缓冲区指针。译注：原题把下一索引简写成 cache_lines[cur]，按前面的结构定义应读取 cache_lines[cur].value。

准备随机索引时，确保一轮链式遍历能够将每条缓存行访问一次，而不只落入一个较小的环。

问题 12

现在可以测量不同访问层次和噪声条件下的性能：

  • L1：让 test_buffer 远小于 L1 容量，例如 2KB，并将噪声配置设为 none；
  • L2：使用相同设置，但增大缓冲区，例如 128KB；
  • L3：继续增大缓冲区，例如 1MB；
  • 本地内存：使用更大的缓冲区，例如 32MB，并确保测试缓冲区位于测试线程所在的 NUMA 节点；
  • 远端内存：改变测试缓冲区的分配节点；
  • 需要噪声时，启用 spread 或 overload 模式。

阅读时留意

32MB 缓冲区超出 L3、每行 64 字节以及各层缓存容量，均属于原题测试环境的假设，应与 lstopo 输出核对。仅分配内存并不等于已完成初始化和预热；实测时应明确这些步骤。顺序读的平均耗时与依赖链随机访问的延迟也不是同一测量条件。
