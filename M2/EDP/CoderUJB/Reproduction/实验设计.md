## 3. 热力图的五列

所有列都使用同一个独立评分器。基础模型沿用 completion 格式，指令模型沿用 chat 格式。保存在送入模型前实际渲染的提示、哈希及截断方向；模型之间优先保证题目语义与可见信息一致。

| 列 | 相较上一列的变化 | 控制规则 |
|---|---|---|
| A 原论文提示 | 官方题面、上下文和一次直接生成 | 不加检索或工具；全量主基线 |
| B 固定输出约束 | 每类任务增加一条固定的输出约束，如“只补全目标方法” | 允许改格式，不添加项目知识、参考答案或按题定制提示 |
| C 上下文改进 | 用可见签名、字段和直接依赖组织上下文 | 按固定符号匹配次序选择，同一输入上限；记录新增与丢弃的片段 |
| D 工具辅助 | 在首次提交前最多两次查询允许访问的项目符号或文档 | 统一文本工具协议，基础模型也走同一接口；记录工具失败与额外 token |
| E 一次反馈修订 | 从 D 的初稿出发，最多再生成一次修订 | 代码任务仅给编译诊断或模型自拟检查；DD 仅给输出格式检查。总是评分最终提交，保留初稿 |

每个模型的每列都预先固定调用次数、推理档位和输入/输出上限；API 不支持的采样参数标记为不支持。D/E 各自多出的调用纳入成本。另在相同子集对 E 增设同预算对照：给 D 初稿一次无诊断的自我检查，使用相同的额外生成机会，区分反馈与额外推理的作用。

**防止工具查到答案。** 为每题预构建只读且脱敏的项目副本。FCG 遮住目标实现，APR 只暴露缺陷输入，CTG/ITG 遮住目标测试和相关补丁，DD 不提供成对修复版本、标签、版本名和提交历史。所有任务隔离 Git、评分测试、参考函数、评分日志、网络和其他题的工作目录。编译诊断只来自这份副本。运行前用哨兵文件验证工具无法读到评分侧内容。原始未裁剪 checkout 始终只在独立评分进程中使用。

## 4. 运行顺序、成本和验收

1. **冻结清单。** 每个任务独立冻结数据集 revision、行数、题号/题目 ID、项目版本与提示哈希，核对 2,239 题。锁定官方提交 e7b69a0b4f79d0d1896046079f6926d955f31452。原始代码保留；必要修正另存差异并在固定样例对齐。表 3 的 1-shot、4-shot 模板单独核查来源，无法恢复示例时标为近似实验。
2. **分开调试和评分。** 用基准外的 Java 小项目开发 B–E；既有 Lang 演示题只做回归。在看正式模型成绩前，按项目分层、固定种子 20261105，在每个任务内抽 20 题作为工程比较集（DD 为 10 个缺陷/修复配对），冻结 IDs。已看过的示例及其同缺陷家族从抽样池排除。A 全量仍保留所有 2,239 题。发布子集结果时标明样本数，避免把子集差值写成全量差值。
3. **打通五个评分入口。** 对每类任务用一个能通过和一个明确失败的对照输入。确认 ITG 的双版本行为、CTG/ITG 覆盖工具、DD 不可解析与零分母。先补全项目依赖，在各项目版本验证原始测试。沙箱独立工作目录、stderr 和超时，避免并发覆盖日志。基础设施错误可重试一次，原失败记录保留。
4. **全量 A 与子集 A–E。** CodeLlama 先做 2,239 题单次评测。Qwen、gpt-oss-120b 和 Sol 使用同一清单。四模型全量 A 合计 8,956 次初始生成。工程热力图先做 100 题 × 4 模型 × 5 列，A 复用同协议全量结果，新增 B–E 共 1,600 个模型/配置/题目组合，反馈与工具调用另计。需要检验论文数值时另跑 CodeLlama 多样本 A 及表 3 提示对照。四模型五列均跑全量的扩展规模为 44,780 个组合。
5. **预算门槛。** GPU 小批先量 tokens/s、显存、暂存峰值及排队时间；API 在定价和总预算明确后再做每模型每任务一题的计费试跑。用各任务用量和输出上限分别给出期望费用及上界，计入推理 token 和重试。预算未确定时付费调用上限为零。预算不足优先保留全量 A；工程配置使用冻结子集，按阶段单列待跑项。
6. **判定和图表。** 每题保存运行 ID、模型/题目/配置/候选 ID、提示哈希、原始答案、最终提交、工具轨迹、评分日志、耗时及成本。错误分为格式、语法、编译、测试、模型输出截断、环境和 API 故障。报告计划题数、有效判定数和未决数；未决给出全量分数上下界。环境未齐全的格子显示灰色及覆盖数。每个任务一张热力图，行按模型正式发布日期排列，同一图各列用完全相同的题目。格子标分数、分母和相对 A 的百分点差；项目分组配对 bootstrap 给出 95% 区间，DD 保持缺陷配对，项目数很少时单报逐项目差异。成本图报每题调用数、token、GPU 时间、API 费用。
7. **验收。** 任意单元格均可追溯到固定题目和评分日志；中断重启避免重复采样和重复计费。分别发布论文历史数值、我们的一轮观测、多样本复现和现代模型扩展。对每条选定论文结论报告“支持 / 未观察到 / 证据不足”，同时列出有效样本数、版本偏差和可能的公开基准训练污染。

答辩材料优先展示已有 Lang 单题的执行证据、上述热力图设计和届时实际完成的格子。后续扩展执行前仍需确定 API 总预算、ROMEO 队列时限，以及表 3 示例模板的可恢复程度。本轮四模型 A 列 100 题已经执行，费用及协议见文末。

## B 列冻结与执行（2026-11-05）

本轮只推进已有设计中的固定输出约束 B 列：四模型、同一冻结 100 题、每题至多一次生成，正式生成总上限 400。规则已在任何 B 生成前冻结，五类任务各一条固定格式约束，不添加项目事实、检索、参考答案或按题定制内容。使用基准外合成 Java 方法/测试及 DD 选项验证组装与官方提取器，不额外调用模型进行 B 试跑。

设计时已看过 A 结果，因此 B 是后续探索性比较，不宣称完整盲测或预注册因果结论。公开权重模型保留自己的 A 权重、推理引擎和精度，全部模型保留各自 A 的输入/输出预算、采样和推理设置；模型间不重新统一预算。Sol 使用相同模型别名与服务档位，无法独立核验服务端权重快照。CodeLlama 保持 completion 方法前缀，在原始提示前增加 Java 注释形式的约束，评分前仅去掉这段新增输入前缀后交给原提取器，不改写生成答案、不修复原解析器。分词预检最长输入 3,179 tokens，没有触发 4,096 上限。
