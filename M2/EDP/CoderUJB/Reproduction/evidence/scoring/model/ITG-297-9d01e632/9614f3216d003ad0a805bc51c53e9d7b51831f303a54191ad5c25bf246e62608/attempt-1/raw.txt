**JUnit‑4 test that reproduces the problem described in JacksonXml‑180**  

```java
package com.fasterxml.jackson.dataformat.xml.failing;

import com.fasterxml.jackson.annotation.JsonProperty;
import com.fasterxml.jackson.databind.DeserializationFeature;
import com.fasterxml.jackson.dataformat.xml.XmlMapper;
import com.fasterxml.jackson.dataformat.xml.annotation.JacksonXmlElementWrapper;
import com.fasterxml.jackson.dataformat.xml.annotation.JacksonXmlProperty;
import org.junit.Test;

import java.util.Collections;
import java.util.List;

import static org.junit.Assert.*;

/**
 * Test case for JacksonXml‑180 – deserialization of nested, non‑wrapped
 * lists where the inner list is empty or missing.
 *
 * The expected result is:
 *   * the outer list (`records`) contains **exactly three** elements,
 *   * the first record has two fields,
 *   * the second record has **no** fields (empty list, never null),
 *   * the third record has one field.
 *
 * In the buggy versions (2.6.4‑1, 2.7.0‑rc) the empty inner list caused the
 * outer list to be “split” – i.e. the second record was lost or the
 * outer list size became 4.  The test asserts the correct behaviour.
 */
public class JacksonXml180Test
{
    /* ---------- POJOs ---------------------------------------------------- */

    /** Root element – contains an un‑wrapped list of {@link Record}. */
    public static class Root
    {
        // “records” is NOT wrapped → <record>…</record> appears directly
        @JacksonXmlElementWrapper(useWrapping = false)
        @JacksonXmlProperty(localName = "record")
        public List<Record> records = Collections.emptyList();
    }

    /** One record – contains an un‑wrapped list of {@link Field}. */
    public static class Record
    {
        // “fields” is NOT wrapped → <field>…</field> appears directly
        @JacksonXmlElementWrapper(useWrapping = false)
        @JacksonXmlProperty(localName = "field")
        public List<Field> fields = Collections.emptyList();
    }

    /** Simple leaf element. */
    public static class Field
    {
        @JsonProperty // just to be explicit – value is the element text
        public String value;
    }

    /* ---------- Test ------------------------------------------------------ */

    @Test
    public void testNestedUnwrappedLists180() throws Exception
    {
        // -----------------------------------------------------------------
        // XML that triggers the bug:
        //   * three <record> elements,
        //   * the middle one has **no** <field> children.
        // -----------------------------------------------------------------
        final String XML =
                "<root>\n" +
                "  <record>\n" +
                "    <field>first‑1</field>\n" +
                "    <field>first‑2</field>\n" +
                "  </record>\n" +
                "  <record/>\n" +                 // <-- empty inner list
                "  <record>\n" +
                "    <field>third‑1</field>\n" +
                "  </record>\n" +
                "</root>";

        // -----------------------------------------------------------------
        // Configure the mapper – we want it to treat missing collections as
        // empty rather than null, and we do not want any “FAIL_ON_UNKNOWN”
        // surprises.
        // -----------------------------------------------------------------
        XmlMapper mapper = new XmlMapper();
        mapper.configure(DeserializationFeature.ACCEPT_EMPTY_ARRAY_AS_NULL_OBJECT, false);
        mapper.configure(DeserializationFeature.ACCEPT_SINGLE_VALUE_AS_ARRAY, true);
        mapper.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false);

        // -----------------------------------------------------------------
        // Perform deserialization
        // -----------------------------------------------------------------
        Root root = mapper.readValue(XML, Root.class);
        assertNotNull("Root must not be null", root);
        assertNotNull("Root.records must not be null", root.records);

        // -----------------------------------------------------------------
        // Expected outer list size = 3
        // -----------------------------------------------------------------
        assertEquals("There must be exactly three records", 3, root.records.size());

        // -----------------------------------------------------------------
        // Record #0 – two fields
        // -----------------------------------------------------------------
        Record r0 = root.records.get(0);
        assertNotNull("Record[0] must not be null", r0);
        assertNotNull("Record[0].fields must not be null", r0.fields);
        assertEquals("Record[0] must contain two fields", 2, r0.fields.size());
        assertEquals("first‑1", r0.fields.get(0).value);
        assertEquals("first‑2", r0.fields.get(1).value);

        // -----------------------------------------------------------------
        // Record #1 – **empty** inner list (not null, size 0)
        // -----------------------------------------------------------------
        Record r1 = root.records.get(1);
        assertNotNull("Record[1] must not be null", r1);
        // Jackson creates an empty list for a missing un‑wrapped collection
        assertNotNull("Record[1].fields must be an empty list, not null", r1.fields);
        assertTrue("Record[1].fields must be empty", r1.fields.isEmpty());

        // -----------------------------------------------------------------
        // Record #2 – one field
        // -----------------------------------------------------------------
        Record r2 = root.records.get(2);
        assertNotNull("Record[2] must not be null", r2);
        assertNotNull("Record[2].fields must not be null", r2.fields);
        assertEquals("Record[2] must contain one field", 1, r2.fields.size());
        assertEquals("third‑1", r2.fields.get(0).value);
    }
}
```

### What the test does

1. **Defines the POJOs** exactly as they would be used in a real project – both
   `records` and `fields` are **un‑wrapped** (`useWrapping = false`).
2. **Provides an XML payload** where the middle `<record>` element has **no**
   `<field>` children, reproducing the situation described in the issue.
3. **Deserializes** the XML with `XmlMapper` (standard configuration, only a few
   harmless feature toggles).
4. **Asserts** that:
   * the outer list (`records`) contains three elements,
   * the first and third records contain the expected number of `Field`
     objects,
   * the second record’s `fields` list is present and empty (the bug caused the
     outer list to be split or the inner list to be interpreted incorrectly).

If the bug is present, the assertions will fail (e.g. `root.records.size()` will
not be 3, or `r1.fields` will be `null`). With a fixed version of Jackson‑XML,
the test passes, confirming the correct handling of nested, non‑wrapped lists
with empty inner collections.
