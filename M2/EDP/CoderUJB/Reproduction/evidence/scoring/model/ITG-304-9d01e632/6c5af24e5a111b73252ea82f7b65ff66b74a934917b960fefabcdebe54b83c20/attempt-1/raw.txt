**JUnit test for CSV‑219 – “Do not quote the first field when it starts with a CJK character”**

```java
package org.apache.commons.csv;

import static org.junit.Assert.assertEquals;

import java.io.IOException;
import java.io.StringWriter;

import org.junit.Test;

/**
 * Test that {@link CSVFormat#EXCEL} behaves like Microsoft Excel when the
 * first column of a record starts with a CJK character.
 *
 * <p>Excel writes the fields without any surrounding quotes:
 *
 * <pre>
 * あ,い,う
 * </pre>
 *
 * The previous implementation of Commons‑CSV produced:
 *
 * <pre>
 * "あ",い,う
 * </pre>
 *
 * This test asserts the correct (Excel‑compatible) output.
 */
public class CsvExcelQuoteTest {

    @Test
    public void testDontQuoteEuroFirstChar() throws IOException {
        // ------------------------------------------------------------
        // 1. Prepare a writer that will receive the CSV output
        // ------------------------------------------------------------
        StringWriter out = new StringWriter();

        // ------------------------------------------------------------
        // 2. Use the Excel‑compatible format (default quote char = ")
        // ------------------------------------------------------------
        try (CSVPrinter printer = new CSVPrinter(out, CSVFormat.EXCEL)) {
            // Record containing three Japanese (CJK) characters
            printer.printRecord("あ", "い", "う");
        }

        // ------------------------------------------------------------
        // 3. Build the expected string.
        //    CSVFormat.EXCEL uses CRLF as the record separator.
        // ------------------------------------------------------------
        String expected = "あ,い,う\r\n";

        // ------------------------------------------------------------
        // 4. Verify that the first field is **not** quoted.
        // ------------------------------------------------------------
        assertEquals("Excel‑compatible CSV output is incorrect", expected, out.toString());
    }
}
```

### What the test does
1. **Creates** a `StringWriter` to capture the CSV text.
2. **Instantiates** a `CSVPrinter` with `CSVFormat.EXCEL`.
3. **Prints** a single record whose first column starts with a CJK character (`"あ"`).
4. **Compares** the generated output with the exact string that Excel would produce (`あ,い,う\r\n`).  
   If the first field is quoted (e.g., `"あ",い,う\r\n`), the assertion fails, exposing the bug described in **Csv‑CSV‑219**.  

Running this test against the current library will highlight the discrepancy; after the fix it will pass, confirming that the library now matches Excel’s quoting behaviour for CJK‑initial fields.
