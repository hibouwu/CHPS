**What was wrong?**  

The original `appendOption` method was a *static* helper that tried to build the usage fragment for an `Option`.  
It had three independent problems that broke the contract of `HelpFormatter`:

| # | Problem | Why it matters |
|---|---------|----------------|
| 1 | **Long option is never shown when a short option exists** – the code only prints `-a` or `--all`. The real CLI usage should display both (`-a,--all`). |
| 2 | **Argument name fallback is missing** – if the option has an argument but `argName` is `null`, the formatter must use the formatter’s default argument name (`defaultArgName`). The old code simply omitted the placeholder. |
| 3 | **The method is static** – it therefore cannot use the configurable prefixes (`defaultOptPrefix`, `defaultLongOptPrefix`) or the default argument name. The hard‑coded `"-"` and `"--"` make the formatter ignore any user‑provided customisation. |

Because of these bugs the generated *usage* string could be incomplete, misleading or completely wrong.

---

## Fixed implementation  

```java
/**
 * Appends the usage clause for an {@link Option} to a {@link StringBuffer}.
 *
 * @param buff     the buffer to append to
 * @param option   the option to render
 * @param required {@code true} if the option is required, {@code false}
 *                 otherwise
 */
private void appendOption(final StringBuffer buff,
                          final Option option,
                          final boolean required) {

    // ----- 1. optional‑brackets for non‑required options -----------------
    if (!required) {
        buff.append('[');
    }

    // ----- 2. option name(s) -------------------------------------------
    // short option (e.g. -h)
    if (option.getOpt() != null) {
        buff.append(defaultOptPrefix).append(option.getOpt());

        // long option together with the short one (e.g. -h,--help)
        if (option.getLongOpt() != null) {
            buff.append(',').append(defaultLongOptPrefix).append(option.getLongOpt());
        }
    }
    // only a long option (e.g. --help)
    else {
        buff.append(defaultLongOptPrefix).append(option.getLongOpt());
    }

    // ----- 3. argument placeholder --------------------------------------
    if (option.hasArg()) {
        // use the option‑specific name if supplied, otherwise the formatter's default
        String argName = option.getArgName();
        if (argName == null) {
            argName = defaultArgName;
        }

        // optional argument – surround the placeholder with brackets
        if (option.hasOptionalArg()) {
            buff.append(" [<").append(argName).append(">]");
        } else {
            buff.append(" <").append(argName).append('>');
        }
    }

    // ----- 4. closing optional bracket ----------------------------------
    if (!required) {
        buff.append(']');
    }
}
```

### Why the new code works

| Fix | Explanation |
|-----|-------------|
| **Method is now an instance method** (`private void …`) | Allows us to honour the formatter’s configurable prefixes (`defaultOptPrefix`, `defaultLongOptPrefix`) and the default argument name (`defaultArgName`). |
| **Both short and long names are emitted** | When a short name exists we always print it. If a long name also exists we append it after a comma (`-h,--help`). This matches the behaviour of the original Apache Commons CLI `HelpFormatter`. |
| **Argument placeholder handling** | If the option takes an argument we always show a placeholder. When the user supplied an explicit `argName` we use it; otherwise we fall back to the formatter’s `defaultArgName`. Optional arguments (`hasOptionalArg()`) are wrapped in `[…]` to make the optionality visible. |
| **Preserves required‑option brackets** | The surrounding `[` … `]` are added only when the option itself is not required, exactly as the original contract specifies. |

With these changes the `HelpFormatter` now produces correct usage strings such as:

```
usage: myapp [-h,--help] [-o,--output <file>] [--verbose]
```

instead of the broken output that omitted the long option, ignored custom prefixes, or left out argument placeholders.
