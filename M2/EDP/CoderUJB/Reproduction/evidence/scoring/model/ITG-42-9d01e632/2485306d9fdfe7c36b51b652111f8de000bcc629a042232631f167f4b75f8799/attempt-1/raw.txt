Below is a **stand‑alone JUnit‑4 test class** that implements the requested test method  
`testEqualsAfterSerializationOfDerivedClass`.  
The test reproduces *COLLECTIONS‑576* by:

1. Defining a **non‑final** subclass of `org.apache.commons.collections4.keyvalue.MultiKey`.  
2. Serialising an instance of that subclass.  
3. Deserialising it again.  
4. Verifying that the **`equals` contract** (and consequently the hash‑code) is preserved after the round‑trip.  

If `MultiKey.readResolve()` remains **private**, the deserialised object will have a different hash‑code (and `equals` will return `false`). Declaring `readResolve` as `protected` (or making `MultiKey` final) fixes the problem.

```java
package de.ivu.test.common.collections4;

import static org.junit.Assert.assertEquals;
import static org.junit.Assert.assertTrue;

import java.io.*;

import org.apache.commons.collections4.keyvalue.MultiKey;
import org.junit.Test;

/**
 * Test that a subclass of {@link MultiKey} keeps its {@code equals} (and hashCode)
 * semantics after being serialized and deserialized.
 *
 * <p>This test reproduces the failure described in
 * <a href="https://issues.apache.org/jira/browse/COLLECTIONS-576">COLLECTIONS‑576</a>.
 * The fix is to make {@code MultiKey.readResolve()} {@code protected} (or to make
 * {@code MultiKey} final).</p>
 */
public class MultiKeyDerivedSerializationTest {

    /**
     * Simple concrete subclass of {@link MultiKey}.  It is deliberately **not**
     * declared {@code final} to trigger the bug when {@code readResolve} is
     * private.
     *
     * @param <A> type of the first key
     * @param <B> type of the second key
     */
    @SuppressWarnings("serial")
    private static class MyMultiKey<A, B> extends MultiKey {

        public MyMultiKey(A key1, B key2) {
            super(key1, key2);
        }

        @SuppressWarnings("unchecked")
        public A getFirst() {
            return (A) getKey(0);
        }

        @SuppressWarnings("unchecked")
        public B getSecond() {
            return (B) getKey(1);
        }
    }

    /**
     * Serialises {@code original}, deserialises it back and checks that the
     * deserialised instance is equal to the original (and therefore has the
     * same hash code).  The test will fail as long as {@code MultiKey.readResolve()}
     * is private.
     *
     * @throws IOException            if an I/O error occurs
     * @throws ClassNotFoundException if the class of a serialized object cannot be found
     */
    @Test
    public void testEqualsAfterSerializationOfDerivedClass()
            throws IOException, ClassNotFoundException {

        // -----------------------------------------------------------------
        // 1. Create the original object (a subclass of MultiKey)
        // -----------------------------------------------------------------
        MyMultiKey<String, Integer> original = new MyMultiKey<>("alpha", 42);

        // -----------------------------------------------------------------
        // 2. Serialise it to a byte array
        // -----------------------------------------------------------------
        byte[] serialized;
        try (ByteArrayOutputStream bos = new ByteArrayOutputStream();
             ObjectOutputStream out = new ObjectOutputStream(bos)) {
            out.writeObject(original);
            out.flush();
            serialized = bos.toByteArray();
        }

        // -----------------------------------------------------------------
        // 3. Deserialise the byte array back into an object
        // -----------------------------------------------------------------
        MyMultiKey<String, Integer> deserialized;
        try (ByteArrayInputStream bis = new ByteArrayInputStream(serialized);
             ObjectInputStream in = new ObjectInputStream(bis)) {
            @SuppressWarnings("unchecked")
            MyMultiKey<String, Integer> tmp = (MyMultiKey<String, Integer>) in.readObject();
            deserialized = tmp;
        }

        // -----------------------------------------------------------------
        // 4. Verify that equals() (and hashCode()) are preserved
        // -----------------------------------------------------------------
        assertTrue("Deserialized object must be equal to the original", original.equals(deserialized));
        assertEquals("Hash codes must be identical after serialization round‑trip",
                original.hashCode(), deserialized.hashCode());
    }
}
```

### How the test works
| Step | What happens | Why it matters |
|------|--------------|----------------|
| **Subclass definition** | `MyMultiKey` extends `MultiKey` and adds typed getters. | The bug only appears when `MultiKey` is subclassed. |
| **Serialization** | The object is written with `ObjectOutputStream`. | Triggers the `writeObject` path that stores the transient `hashCode`. |
| **Deserialization** | The object is read back with `ObjectInputStream`. | If `readResolve` is private, it is **not** invoked for the subclass, leaving the transient `hashCode` at its default value (`0`). |
| **Equality & hash‑code check** | `assertTrue(original.equals(deserialized))` and `assertEquals(original.hashCode(), deserialized.hashCode())`. | When `readResolve` runs correctly, the deserialized instance recomputes the cached hash‑code, making the two objects equal. If not, the test fails, exposing the issue. |

Running this test against the current (buggy) version of Commons‑Collections‑4 will **fail**, confirming the problem. After applying the fix (making `readResolve` `protected` or declaring `MultiKey` final), the test passes.
