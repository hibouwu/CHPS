**What was wrong?**

| Issue | Why it is a bug | Consequence |
|-------|----------------|-------------|
| `if (str == "true")` | Uses reference equality instead of content comparison. Only works when the literal `"true"` is *interned* (the same object). | For any other `"true"` string (e.g. `new String("true")`) the method falls through to the `switch` and still works, but the special‑case optimisation is lost. |
| `null` check after the `"true"` test | The method later calls `str.length()` and `str.charAt(..)`. If `str` is `null` the first test (`str == "true"`) is safe, but the `null` test is placed **after** it, which is confusing and makes the intent harder to read. | No functional error, but it is a maintenance risk. |
| Missing `break`/`return` in the `case 3` block of the `switch` | After evaluating a 3‑character string that is **not** `"yes"` the execution falls through to `case 4`. `case 4` accesses `str.charAt(3)`, which does **not exist** for a length‑3 string. | `StringIndexOutOfBoundsException` for inputs like `"no"` or `"abc"`. |
| Redundant duplicated logic for the first character of `"yes"` and `"YES"` | Two almost identical branches (`if (ch == 'y') …` and `if (ch == 'Y') …`). | No functional bug, but makes the code harder to maintain. |

---

## Fixed implementation

```java
package org.apache.commons.lang;

public class BooleanUtils {

    // -----------------------------------------------------------------------
    // String to boolean methods
    /**
     * <p>Converts a {@link String} to a {@code boolean} (optimised for performance).</p>
     *
     * <p>Accepts the case‑insensitive values {@code "true"}, {@code "on"} and {@code "yes"}.
     * Anything else – including {@code null} – yields {@code false}.</p>
     *
     * @param str the {@code String} to check, may be {@code null}
     * @return {@code true} if the string matches one of the accepted true values,
     *         otherwise {@code false}
     */
    public static boolean toBoolean(String str) {
        // 1️⃣  Guard clause – null is always false.
        if (str == null) {
            return false;
        }

        // 2️⃣  Switch on length – this avoids the cost of creating a temporary
        //     lower‑cased copy and is faster than a series of equalsIgnoreCase calls.
        switch (str.length()) {
            case 2: // "on"
                return (str.charAt(0) == 'o' || str.charAt(0) == 'O')
                    && (str.charAt(1) == 'n' || str.charAt(1) == 'N');

            case 3: // "yes"
                char c0 = str.charAt(0);
                if (c0 == 'y' || c0 == 'Y') {
                    return (str.charAt(1) == 'e' || str.charAt(1) == 'E')
                        && (str.charAt(2) == 's' || str.charAt(2) == 'S');
                }
                // not "yes" → false
                return false;

            case 4: // "true"
                c0 = str.charAt(0);
                if (c0 == 't' || c0 == 'T') {
                    return (str.charAt(1) == 'r' || str.charAt(1) == 'R')
                        && (str.charAt(2) == 'u' || str.charAt(2) == 'U')
                        && (str.charAt(3) == 'e' || str.charAt(3) == 'E');
                }
                // not "true" → false
                return false;

            default: // any other length cannot be a true value
                return false;
        }
    }

    // -----------------------------------------------------------------------
    // other methods of BooleanUtils would be here …
}
```

### What changed and why

1. **Null‑check moved to the top** – makes the method safe and clearer.
2. **Removed the `str == "true"` reference‑equality optimisation** – it was unreliable and added no real benefit because the case‑4 block already handles `"true"` in a case‑insensitive way.
3. **Added explicit `return false` for the 3‑character branch** – prevents fall‑through to the 4‑character block and eliminates the `StringIndexOutOfBoundsException`.
4. **Simplified the `"yes"` handling** – a single test for `y`/`Y` is enough; the subsequent characters are already checked case‑insensitively.
5. **Added a `default` case** – makes the intent explicit that any other length returns `false`.
6. **Improved documentation and added inline comments** – clarifies the algorithm and its performance rationale.

The method now behaves exactly as specified in the Javadoc, is safe for all inputs, and retains the original performance‑oriented design.
