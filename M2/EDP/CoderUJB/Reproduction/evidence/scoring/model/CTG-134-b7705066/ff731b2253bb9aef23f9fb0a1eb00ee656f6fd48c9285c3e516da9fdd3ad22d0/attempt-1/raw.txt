```java
/**
 * Test case for
 * <a href="https://issues.apache.org/jira/browse/COMPRESS-351">COMPRESS-351</a>.
 *
 * The test builds a minimal ZIP archive in memory, then deliberately corrupts the
 * *file‑name length* field in the first Local File Header.  When {@link ZipArchiveInputStream}
 * tries to read the entry it should detect the inconsistency and throw an
 * {@link IOException} (normally a {@link java.util.zip.ZipException}) whose
 * message mentions that the entry is corrupt or invalid.
 *
 * The test asserts that an exception is thrown and that its message contains
 * an indication of the problem.
 */
@Test
public void testMessageWithCorruptFileName() throws Exception {
    /* -------------------------------------------------------------
     * 1. Create a well‑formed ZIP containing a single entry.
     * ------------------------------------------------------------- */
    final ByteArrayOutputStream baos = new ByteArrayOutputStream();
    try (java.util.zip.ZipOutputStream zos = new java.util.zip.ZipOutputStream(baos)) {
        java.util.zip.ZipEntry ze = new java.util.zip.ZipEntry("test.txt");
        ze.setSize(5);
        zos.putNextEntry(ze);
        zos.write("hello".getBytes("UTF-8"));
        zos.closeEntry();
    }

    /* -------------------------------------------------------------
     * 2. Corrupt the *file‑name length* field of the first Local File
     *    Header (LFH).  LFH layout (little‑endian):
     *    0  – 3 : signature (0x04034b50)
     *    26 –27 : file‑name length (2 bytes)
     * ------------------------------------------------------------- */
    byte[] zipBytes = baos.toByteArray();

    // locate the first LFH signature
    final int LFH_SIG = 0x04034b50;
    int lfhPos = -1;
    for (int i = 0; i < zipBytes.length - 3; i++) {
        int sig = ((zipBytes[i] & 0xff)) |
                  ((zipBytes[i + 1] & 0xff) << 8) |
                  ((zipBytes[i + 2] & 0xff) << 16) |
                  ((zipBytes[i + 3] & 0xff) << 24);
        if (sig == LFH_SIG) {
            lfhPos = i;
            break;
        }
    }
    assertTrue("Local File Header not found in generated zip", lfhPos >= 0);

    // offset of the file‑name length field inside the LFH
    final int FILE_NAME_LEN_OFFSET = lfhPos + 26;
    // set it to an absurdly large value (0xFFFF) – larger than the remaining
    // bytes in the archive – to provoke a corrupt‑name situation.
    zipBytes[FILE_NAME_LEN_OFFSET] = (byte) 0xFF;
    zipBytes[FILE_NAME_LEN_OFFSET + 1] = (byte) 0xFF;

    /* -------------------------------------------------------------
     * 3. Try to read the corrupted archive with ZipArchiveInputStream.
     * ------------------------------------------------------------- */
    try (ZipArchiveInputStream zis = new ZipArchiveInputStream(
            new ByteArrayInputStream(zipBytes), null, true, true)) {

        // The call that should fail – it attempts to read the entry name.
        zis.getNextZipEntry();

        // If we reach this line the implementation failed to detect the problem.
        fail("Expected an IOException due to a corrupt file name, but none was thrown.");
    } catch (IOException e) {
        // The message should contain a hint that the entry is corrupt/invalid.
        String msg = e.getMessage() == null ? "" : e.getMessage().toLowerCase();
        assertTrue("Exception message should mention a corrupt or invalid entry name, but was: " + e.getMessage(),
                msg.contains("corrupt") || msg.contains("invalid") || msg.contains("zip"));
    }
}
```

**Explanation of the test**

1. **Create a valid ZIP** – a `ByteArrayOutputStream` is wrapped by a `java.util.zip.ZipOutputStream`. One entry (`test.txt`) with the content `"hello"` is written.

2. **Corrupt the LFH** – the test scans the generated byte array for the Local File Header signature (`0x04034b50`). Once found, it overwrites the two‑byte *file‑name length* field (offset + 26) with `0xFFFF`. This makes the parser believe the name is 65 535 bytes long, far beyond the actual data, which forces `ZipArchiveInputStream` to encounter an unexpected end of stream while reading the name.

3. **Read with `ZipArchiveInputStream`** – the corrupted byte array is fed to a new `ZipArchiveInputStream`. The call to `getNextZipEntry()` must fail. The test asserts that an `IOException` (normally a `ZipException`) is thrown and that its message contains a word such as *corrupt*, *invalid*, or *zip* – the wording used by the library for this situation.

If the implementation correctly detects the malformed file‑name, the test passes; otherwise it fails, highlighting the regression described in **COMPRESS‑351**.
