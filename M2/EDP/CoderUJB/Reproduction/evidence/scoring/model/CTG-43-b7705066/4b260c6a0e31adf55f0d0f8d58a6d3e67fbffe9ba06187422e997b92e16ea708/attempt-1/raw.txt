**Test class – `TestUnsupportedDateTimeField`**

```java
package org.joda.time.field;

import java.util.Locale;

import junit.framework.TestCase;
import junit.framework.TestSuite;

import org.joda.time.DateTimeField;
import org.joda.time.DateTimeFieldType;
import org.joda.time.DurationField;
import org.joda.time.chrono.ISOChronology;

/**
 * JUnit‑3 test suite for {@link UnsupportedDateTimeField}.
 *
 * The method {@code testMethodsThatShouldAlwaysReturnNull()} verifies the two
 * Javadoc‑specified methods that must always return {@code null}:
 *
 * <ul>
 *   <li>{@link UnsupportedDateTimeField#getRangeDurationField()}</li>
 *   <li>{@link UnsupportedDateTimeField#getLeapDurationField()}</li>
 * </ul>
 *
 * The test creates an {@code UnsupportedDateTimeField} instance via the
 * {@code getInstance(..)} factory method and asserts that both calls return
 * {@code null}.
 */
public class TestUnsupportedDateTimeField extends TestCase {

    /** A concrete {@link DurationField} used for the factory call – weeks. */
    private DurationField weeksDuration;

    /** A concrete {@link DateTimeFieldType} – hour of day (any type works). */
    private DateTimeFieldType hourOfDayType;

    /** -------------------------------------------------------------------- */
    /** Boiler‑plate for JUnit‑3 ------------------------------------------------ */
    /** -------------------------------------------------------------------- */
    public static TestSuite suite() {
        return new TestSuite(TestUnsupportedDateTimeField.class);
    }

    @Override
    protected void setUp() throws Exception {
        super.setUp();
        // ISOChronology provides real DurationField implementations.
        weeksDuration = ISOChronology.getInstanceUTC().weeks();
        hourOfDayType = DateTimeFieldType.hourOfDay();
    }

    /** -------------------------------------------------------------------- */
    /** The requested test --------------------------------------------------- */
    /** -------------------------------------------------------------------- */
    /**
     * According to the JavaDocs, there are two methods that should always
     * return {@code null}:
     *
     * <ul>
     *   <li>{@code getRangeDurationField()}</li>
     *   <li>{@code getLeapDurationField()}</li>
     * </ul>
     *
     * Ensure that these are in fact {@code null}.
     */
    public void testMethodsThatShouldAlwaysReturnNull() {
        // -----------------------------------------------------------------
        // Create an UnsupportedDateTimeField instance.  The concrete
        // DurationField we pass (weeks) is irrelevant – the class stores it
        // but never uses it for the two methods we are testing.
        // -----------------------------------------------------------------
        DateTimeField field = UnsupportedDateTimeField.getInstance(
                hourOfDayType,
                weeksDuration);

        // -----------------------------------------------------------------
        // Verify the contract: both methods must return null.
        // -----------------------------------------------------------------
        assertNull(
                "UnsupportedDateTimeField#getRangeDurationField() must return null",
                field.getRangeDurationField());

        assertNull(
                "UnsupportedDateTimeField#getLeapDurationField() must return null",
                field.getLeapDurationField());
    }

    /* --------------------------------------------------------------------- */
    /* The remaining test methods are declared in the abstract skeleton and */
    /* would be implemented elsewhere.                                      */
    /* --------------------------------------------------------------------- */
}
```

### Explanation of the test

1. **Setup** – `setUp()` obtains a real `DurationField` (`weeks`) from the ISO chronology and a
   `DateTimeFieldType` (`hourOfDay`).  
   Any concrete field type works; the choice is only to keep the test readable.

2. **Instance creation** – The static factory `UnsupportedDateTimeField.getInstance(..)` is used
   (the class under test provides a cache, so the call is the canonical way to obtain an
   instance).

3. **Assertions** –  
   * `assertNull(field.getRangeDurationField())` checks the first Javadoc‑specified method.  
   * `assertNull(field.getLeapDurationField())` checks the second.

Both assertions will pass only if the implementation respects the documented contract,
i.e., the two methods always return `null`. The test follows the JUnit‑3 style used by the
original abstract test class.
