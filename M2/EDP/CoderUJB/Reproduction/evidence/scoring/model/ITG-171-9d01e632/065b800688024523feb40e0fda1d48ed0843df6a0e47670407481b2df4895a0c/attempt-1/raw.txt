**Java – JUnit test for the HW‑rule bug (Codec‑CODEC‑199)**  

```java
import static org.junit.Assert.assertEquals;

import org.junit.Test;

/**
 * Tests for the Soundex implementation (Codec‑CODEC‑199).
 *
 * The American Soundex rule states:
 *   “If two letters that map to the same code are separated by H or W,
 *    the second one is NOT encoded.”
 *
 * The buggy implementation also suppresses a letter when it is
 * preceded by *two* H/W characters, even when the previous
 * consonant maps to a *different* code.  The word “BHWK” exposes
 * this problem:
 *
 *   B → first letter (kept)
 *   H,W → ignored
 *   K → maps to code 2 (different from the previous consonant B which maps to 1)
 *
 * Correct Soundex code:  B200
 * Buggy code (skip because of two preceding H/W): B000
 */
public class SoundexTest {

    @Test
    public void testHWRuleEx1() {
        // Arrange – the word that triggers the faulty logic
        String input = "BHWK";

        // Act – obtain the Soundex code using the class under test
        String actual = Soundex.encode(input);   // static helper or new Soundex().encode(input)

        // Assert – the second consonant (K) must be encoded
        String expected = "B200";
        assertEquals("HW‑rule handling is incorrect for input \"" + input + "\"",
                     expected, actual);
    }
}
```

**Explanation**

* **Input** – `"BHWK"` contains two consecutive `H`/`W` characters before the final consonant `K`.
* **Expected behaviour** – Since the previous encoded consonant (`B`) maps to a different Soundex digit (`1`) than `K` (`2`), the `K` must be encoded, yielding the Soundex code `B200`.
* **Bug manifestation** – The faulty logic treats any character preceded by two `H`/`W` as a duplicate and would return `B000`.
* The test asserts the correct result, thereby detecting the regression introduced by the bug described in issue **Codec‑CODEC‑199**.
