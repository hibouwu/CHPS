**Explanation of the problems**

The original implementation of `equal(GeneralPath, GeneralPath)` contains two independent bugs that make the method return wrong results (or even throw an exception) for many legitimate inputs.

| # | Bug | Why it is wrong | Consequence |
|---|-----|----------------|-------------|
| 1 | `PathIterator iterator2 = p1.getPathIterator(null);` | The second iterator is created from **p1** again instead of **p2**. | The method compares the same path with itself, so two different `GeneralPath` objects are never detected as different. |
| 2 | `Arrays.equals(d1, d2)` compares the whole 6‑element arrays | `PathIterator.currentSegment(double[])` fills only the first *n* entries (2, 4, 6 or 0) depending on the segment type. The remaining entries keep the values from the previous iteration. | Two identical paths can be reported as different because stale values are compared, and two different paths can be reported as equal if the “extra” slots happen to match. |

Both bugs are independent of the rest of the class, therefore fixing them restores the intended semantics of the method.

---

## Fixed implementation

```java
/**
 * Tests two {@link GeneralPath} objects for equality.  If both are
 * {@code null} this method returns {@code true}.
 *
 * @param p1  path 1 (<code>null</code> permitted).
 * @param p2  path 2 (<code>null</code> permitted).
 *
 * @return {@code true} if the two paths are equal, {@code false} otherwise.
 */
public static boolean equal(GeneralPath p1, GeneralPath p2) {
    // ----- null handling -------------------------------------------------
    if (p1 == null) {
        return (p2 == null);
    }
    if (p2 == null) {
        return false;
    }

    // ----- winding rule --------------------------------------------------
    if (p1.getWindingRule() != p2.getWindingRule()) {
        return false;
    }

    // ----- iterate over both paths ---------------------------------------
    PathIterator iterator1 = p1.getPathIterator(null);
    PathIterator iterator2 = p2.getPathIterator(null);   // <-- bug fixed

    double[] d1 = new double[6];
    double[] d2 = new double[6];

    while (!iterator1.isDone() && !iterator2.isDone()) {

        int seg1 = iterator1.currentSegment(d1);
        int seg2 = iterator2.currentSegment(d2);

        // segment type must be identical
        if (seg1 != seg2) {
            return false;
        }

        // compare only the coordinates that are actually used for this segment
        int coordCount;
        switch (seg1) {
            case PathIterator.SEG_MOVETO:
            case PathIterator.SEG_LINETO:
                coordCount = 2;   // x, y
                break;
            case PathIterator.SEG_QUADTO:
                coordCount = 4;   // x1, y1, x2, y2
                break;
            case PathIterator.SEG_CUBICTO:
                coordCount = 6;   // x1, y1, x2, y2, x3, y3
                break;
            case PathIterator.SEG_CLOSE:
                coordCount = 0;   // no coordinates
                break;
            default:
                // Should never happen, but be defensive
                throw new IllegalStateException("Unknown segment type: " + seg1);
        }

        // compare the relevant slice of the coordinate arrays
        for (int i = 0; i < coordCount; i++) {
            if (Double.doubleToLongBits(d1[i]) != Double.doubleToLongBits(d2[i])) {
                return false;
            }
        }

        iterator1.next();
        iterator2.next();
    }

    // Both iterators must finish at the same time
    return iterator1.isDone() && iterator2.isDone();
}
```

### What changed?

1. **Correct iterator for the second path**  
   ```java
   PathIterator iterator2 = p2.getPathIterator(null);
   ```
   This makes the method compare *p1* with *p2* instead of comparing *p1* with itself.

2. **Coordinate‑wise comparison limited to the used slots**  
   * The number of coordinates required for each segment type is derived with a `switch`.  
   * Only those coordinates are compared (`for (int i = 0; i < coordCount; i++) …`).  
   * The comparison uses `Double.doubleToLongBits` (or `Double.compare`) to avoid problems with `-0.0` vs `+0.0` and to keep the test exact, matching the semantics of the original JFreeChart code.

3. **Loop condition** – The loop now runs while **both** iterators have not finished. After the loop we verify that *both* are done; this is equivalent to the original `done` flag logic but clearer.

4. **Defensive error handling** – An `IllegalStateException` is thrown if an unknown segment type appears, which should never happen with a well‑formed `GeneralPath`.

With these corrections the method now behaves exactly as documented: it returns `true` only when the two `GeneralPath` instances have the same winding rule and an identical sequence of path segments (including the same coordinates).
