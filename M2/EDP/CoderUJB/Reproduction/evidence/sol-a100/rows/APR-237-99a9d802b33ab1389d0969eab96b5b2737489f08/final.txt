The issue is the method’s `private` visibility. Although it works for `MultiKey` itself, a private `readResolve()` is not inherited by subclasses. Deserializing a subclass may therefore leave the transient cached hash code at its default value of `0`.

Make the method `protected` so Java serialization can use it for subclasses as well:

```java
/**
 * Recalculates the hash code after deserialization. The hash codes of some
 * keys might have changed (identity-based hash codes are only stable
 * within the same process).
 *
 * @return this instance with its hash code recalculated
 */
protected Object readResolve() {
    calculateHashCode(keys);
    return this;
}
```

The recalculation and return value are already correct; the visibility is what needs fixing.
