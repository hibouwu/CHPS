**JUnit test (Jackson‑Databind 8.10)**  

```java
package com.fasterxml.jackson.databind.ext;

import static org.junit.Assert.*;

import java.util.*;

import com.fasterxml.jackson.databind.*;
import org.junit.Test;

/**
 * Test for JacksonDatabind‑810 – “Force value coercion for java.util.Properties,
 * so that values are Strings”.
 *
 * The test verifies that when a generic {@code Map<String,Object>} (or any
 * other POJO) is converted to {@code java.util.Properties} the values are
 * coerced to {@code String}s, regardless of the original Java type.
 */
public class PropertiesCoercionTest
{
    private final ObjectMapper MAPPER = new ObjectMapper();

    @Test
    public void testMapToProperties() throws Exception
    {
        /*--------------------------------------------------------------
         * 1. Build a Map with heterogeneous value types
         *--------------------------------------------------------------*/
        Map<String,Object> source = new LinkedHashMap<>();
        source.put("int",   42);                     // Integer
        source.put("bool",  Boolean.TRUE);           // Boolean
        source.put("list",  Arrays.asList("a","b")); // List
        source.put("null",  null);                   // null value

        /*--------------------------------------------------------------
         * 2. Convert the Map into a java.util.Properties instance
         *--------------------------------------------------------------*/
        Properties props = MAPPER.convertValue(source, Properties.class);
        assertNotNull("Conversion must produce a non‑null Properties object", props);

        /*--------------------------------------------------------------
         * 3. Verify that every entry is stored as a String
         *--------------------------------------------------------------*/
        // integer → "42"
        assertEquals("42", props.getProperty("int"));
        // boolean → "true"
        assertEquals("true", props.getProperty("bool"));
        // list → its toString() representation (Jackson uses standard Java
        // conversion when coercing a non‑String value to String)
        assertEquals("[a, b]", props.getProperty("list"));
        // null → the literal string "null" (Jackson treats null as the
        // Java null reference, which results in the property being absent)
        assertNull("Null values must not be stored as a property", props.getProperty("null"));

        /*--------------------------------------------------------------
         * 4. Round‑trip: write the Properties as JSON and read it back.
         *    All values must still be JSON strings.
         *--------------------------------------------------------------*/
        String json = MAPPER.writeValueAsString(props);
        // The JSON representation must contain quoted string values
        assertTrue("JSON must contain a quoted string for the int entry",
                json.matches(".*\"int\"\\s*:\\s*\"42\".*"));
        assertTrue("JSON must contain a quoted string for the bool entry",
                json.matches(".*\"bool\"\\s*:\\s*\"true\".*"));
        assertTrue("JSON must contain a quoted string for the list entry",
                json.matches(".*\"list\"\\s*:\\s*\"\\[a, b\\]\".*"));

        // Read the JSON back into a Properties instance – values must stay strings
        Properties roundTrip = MAPPER.readValue(json, Properties.class);
        assertEquals("42", roundTrip.getProperty("int"));
        assertEquals("true", roundTrip.getProperty("bool"));
        assertEquals("[a, b]", roundTrip.getProperty("list"));
    }
}
```

### What the test proves

1. **Conversion from `Map<String,Object>` → `Properties`**  
   *All values are coerced to `String`s* – even numbers, booleans, collections,
   and other non‑String objects.

2. **Serialisation of `Properties` → JSON**  
   The generated JSON contains quoted string values, confirming that the
   `Properties` instance holds only strings.

3. **Deserialisation JSON → `Properties`**  
   When the JSON is read back, the values remain strings, demonstrating that the
   coercion is stable across a full read/write cycle.

If the issue **JacksonDatabind‑810** is fixed, this test will pass; otherwise it
will fail, exposing the missing coercion logic for `java.util.Properties`.
