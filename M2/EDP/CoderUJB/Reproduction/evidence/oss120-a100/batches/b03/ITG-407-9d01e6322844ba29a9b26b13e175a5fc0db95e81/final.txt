**Test case – `testUnexpectedToken`**

```java
package com.google.gson.functional;

import static org.junit.Assert.*;

import com.google.gson.*;
import com.google.gson.stream.JsonReader;
import java.io.StringReader;
import java.util.Date;
import org.junit.Test;

/**
 * Re‑creates the regression introduced by
 * https://github.com/google/gson/commit/b8f616c (Gson‑1100).
 *
 * <p>The problem was that {@code DefaultDateTypeAdapter} stopped being
 * null‑safe after it was migrated to a streaming adapter.  As a result
 * deserialising a JSON document that contains a {@code null} value for a
 * {@code Date} field threw a {@link JsonSyntaxException} (or a
 * {@link NullPointerException}) instead of returning {@code null}.  The
 * same change also broke the contract for JSON primitives – an unexpected
 * token (e.g. an object where a string is expected) should result in a
 * clear {@code JsonSyntaxException}.</p>
 *
 * <p>This test verifies both behaviours:</p>
 * <ul>
 *   <li>Deserialising a {@code null} date is safe and yields {@code null}.</li>
 *   <li>Deserialising a date from an unexpected token (BEGIN_OBJECT) throws
 *       a {@code JsonSyntaxException} whose message mentions the unexpected
 *       token.</li>
 * </ul>
 */
public class DefaultDateTypeAdapterTest {

    /** Simple bean used for the (de)serialisation tests. */
    private static final class Bean {
        Date date;
    }

    @Test
    public void testUnexpectedToken() throws Exception {
        // --------------------------------------------------------------------
        // 1.  Null‑safety check – the adapter must accept a JSON null value.
        // --------------------------------------------------------------------
        Gson gson = new GsonBuilder()
                // any date format works – we only need the default adapter.
                .setDateFormat("yyyy-MM-dd'T'HH:mm:ssZ")
                .create();

        String jsonWithNull = "{\"date\":null}";
        Bean beanFromNull = gson.fromJson(jsonWithNull, Bean.class);

        // The date field must be null – no exception must have been thrown.
        assertNull("Date should be null when JSON contains null", beanFromNull.date);

        // Serialising a bean that contains a null date must produce the literal
        // "null" for the field.
        Bean beanToSerialize = new Bean(); // date == null
        String jsonOut = gson.toJson(beanToSerialize);
        assertEquals("Serialisation of null date must emit null literal",
                     "{\"date\":null}", jsonOut);

        // --------------------------------------------------------------------
        // 2.  Unexpected token – a JSON object where a string (or number) is
        //     expected for a date must raise a JsonSyntaxException.
        // --------------------------------------------------------------------
        String jsonWithObject = "{\"date\":{}}";

        try {
            gson.fromJson(jsonWithObject, Bean.class);
            fail("Expected JsonSyntaxException because a BEGIN_OBJECT token was "
               + "encountered where a JSON primitive (string/number) was expected.");
        } catch (JsonSyntaxException e) {
            // The message produced by the streaming adapter contains the token
            // name; we only assert that it mentions the unexpected token.
            assertTrue("Exception message should contain BEGIN_OBJECT",
                       e.getMessage().contains("BEGIN_OBJECT"));
        }

        // --------------------------------------------------------------------
        // 3.  Low‑level streaming check – the same behaviour must be observed
        //     when using JsonReader directly (the adapter is a TreeTypeAdapter).
        // --------------------------------------------------------------------
        JsonReader reader = new JsonReader(new StringReader("{\"date\":{}}"));
        reader.beginObject();
        reader.nextName(); // "date"
        try {
            // Directly invoke the DefaultDateTypeAdapter via Gson's internal
            // TypeAdapter for Date.
            TypeAdapter<Date> dateAdapter = gson.getAdapter(Date.class);
            dateAdapter.read(reader); // should fail
            fail("Expected JsonSyntaxException from streaming adapter");
        } catch (JsonSyntaxException e) {
            assertTrue(e.getMessage().contains("BEGIN_OBJECT"));
        } finally {
            reader.close();
        }
    }
}
```

### Why this test satisfies **Gson‑1100**

* **Null‑safety** – The test deserialises `{"date":null}` and asserts that the resulting `Bean.date` is `null`. This reproduces the regression reported in issues #1096 and #1098 where Gson 2.8.1 threw an exception for a null date.

* **JSON primitives contract** – By feeding `{"date":{}}` (an object token) the test expects a `JsonSyntaxException` whose message mentions `BEGIN_OBJECT`. This matches the contract that a *primitive* (string/number) is required for a date and that an unexpected token must be reported clearly (issue #1095).

* **Streaming path verification** – The same scenario is exercised through a raw `JsonReader` to guarantee that the new streaming implementation of `DefaultDateTypeAdapter` behaves correctly.

Running this test against a fixed version of Gson (≥ 2.8.2) will pass, while the buggy 2.8.1 version will fail either on the null‑safety assertion or on the unexpected‑token check, confirming the regression described in **Gson‑1100**.
