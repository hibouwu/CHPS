Below is a **stand‑alone JUnit test** that captures the regression described in **Time‑112**.  
It verifies that the legacy three‑letter ID **“MET”** is **not** mapped to the Iranian time‑zone *Asia/Tehran* and that it behaves like the proper **Middle European Time** (UTC+01:00 in winter, UTC+02:00 in summer).

```java
package org.example.timezone;

import static org.junit.Assert.*;

import org.joda.time.DateTime;
import org.joda.time.DateTimeZone;
import org.junit.Test;

/**
 * Test for issue Time‑112 – “Incorrect mapping of the MET time zone”.
 *
 * <p>
 * The historic three‑letter ID “MET” should resolve to Middle European Time
 * (UTC+01:00 / UTC+02:00) and **must not** resolve to “Asia/Tehran”.
 * This test asserts the correct behaviour.
 * </p>
 */
public class MetTimeZoneTest {

    /**
     * Verifies the old three‑letter ID handling for “MET”.
     *
     * <ul>
     *   <li>the returned {@link DateTimeZone} is not {@code null}</li>
     *   <li>its ID is **not** {@code "Asia/Tehran"}</li>
     *   <li>the offset for a winter instant is +01:00 (3600 000 ms)</li>
     *   <li>the offset for a summer instant is +02:00 (7200 000 ms)</li>
     * </ul>
     */
    @Test
    public void testForID_String_old() {
        // ------------------------------------------------------------
        // 1️⃣  Resolve the legacy ID
        // ------------------------------------------------------------
        DateTimeZone metZone = DateTimeZone.forID("MET");
        assertNotNull("MET should resolve to a DateTimeZone instance", metZone);

        // ------------------------------------------------------------
        // 2️⃣  Guard against the historic bug (wrong mapping to Tehran)
        // ------------------------------------------------------------
        assertNotEquals(
                "MET must NOT be mapped to Asia/Tehran (bug Time‑112)",
                "Asia/Tehran",
                metZone.getID()
        );

        // ------------------------------------------------------------
        // 3️⃣  Verify the correct offsets (Middle European Time)
        // ------------------------------------------------------------
        // a) Winter – standard time (UTC+01:00)
        long winterInstant = new DateTime(2020, 1, 15, 0, 0, DateTimeZone.UTC).getMillis();
        assertEquals(
                "Winter offset for MET should be +01:00",
                3_600_000,                     // 1 hour in milliseconds
                metZone.getOffset(winterInstant)
        );

        // b) Summer – daylight saving time (UTC+02:00)
        long summerInstant = new DateTime(2020, 7, 15, 0, 0, DateTimeZone.UTC).getMillis();
        assertEquals(
                "Summer offset for MET should be +02:00",
                7_200_000,                     // 2 hours in milliseconds
                metZone.getOffset(summerInstant)
        );
    }
}
```

### How the test satisfies the issue

| Requirement (derived from the issue) | Test implementation |
|--------------------------------------|----------------------|
| **MET must map to Middle European Time** | Checks winter (`+01:00`) and summer (`+02:00`) offsets. |
| **Must not map to Asia/Tehran** | `assertNotEquals("Asia/Tehran", metZone.getID())`. |
| **Regression guard** | The test will fail if a future change re‑introduces the wrong mapping, ensuring the bug cannot slip back in. |
