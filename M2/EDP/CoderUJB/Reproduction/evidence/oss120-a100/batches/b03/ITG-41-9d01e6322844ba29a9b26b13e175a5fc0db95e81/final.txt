**Test case – `testGenericSignature1195`**

```java
package com.fasterxml.jackson.databind.jdk;

import java.util.concurrent.atomic.AtomicReference;

import com.fasterxml.jackson.databind.type.TypeFactory;
import com.fasterxml.jackson.databind.type.JavaType;

import org.junit.Test;
import static org.junit.Assert.*;

/**
 * Test for JacksonDatabind‑1194.
 *
 * The generic signature that is produced for a parametrized type must contain the
 * closing ‘>’ character.  The bug caused signatures such as
 *
 *   ()Ljava/util/concurrent/atomic/AtomicReference<Ljava/lang/String;;
 *
 * (note the double ‘;’ and the missing ‘>’) to be generated.
 *
 * The correct signature is
 *
 *   ()Ljava/util/concurrent/atomic/AtomicReference<Ljava/lang/String;>;
 *
 * This test builds a {@link JavaType} for {@code AtomicReference<String>} and
 * verifies that the generated generic signature matches the expected one.
 */
public class GenericSignature1194Test
{
    @Test
    public void testGenericSignature1195() throws Exception
    {
        // -----------------------------------------------------------------
        // 1. Build the JavaType for AtomicReference<String>
        // -----------------------------------------------------------------
        TypeFactory tf = TypeFactory.defaultInstance();
        JavaType type = tf.constructParametricType(AtomicReference.class, String.class);

        // -----------------------------------------------------------------
        // 2. Obtain the generic signature
        // -----------------------------------------------------------------
        String signature = type.getGenericSignature();

        // -----------------------------------------------------------------
        // 3. Expected signature (the method‑type prefix “()” is added by
        //    JavaType#getGenericSignature for consistency with method
        //    signatures – see the issue discussion)
        // -----------------------------------------------------------------
        String expected = "()Ljava/util/concurrent/atomic/AtomicReference<Ljava/lang/String;>;";

        // -----------------------------------------------------------------
        // 4. Verify that the signature is exactly as expected
        // -----------------------------------------------------------------
        assertEquals("Generic signature is malformed – missing closing '>'",
                     expected, signature);
    }
}
```

### What the test does

1. **Creates** a `JavaType` that represents `AtomicReference<String>` using Jackson’s `TypeFactory`.
2. **Calls** `JavaType#getGenericSignature()` to obtain the JVM‑style generic signature string.
3. **Compares** the produced signature with the correct one (`()Ljava/util/concurrent/atomic/AtomicReference<Ljava/lang/String;>;`).
4. **Fails** if the closing `>` is omitted (the buggy output would be `...<Ljava/lang/String;;`).

Running this test against a version of Jackson that still contains the bug will cause it to fail, while a fixed version will pass, confirming that the issue **JacksonDatabind‑1194** has been resolved.
