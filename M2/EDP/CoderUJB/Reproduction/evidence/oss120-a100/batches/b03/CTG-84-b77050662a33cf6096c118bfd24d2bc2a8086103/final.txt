Below is a complete implementation of **`testGetOneLineOneParser`** that follows the description *“Tests reusing a parser to process new string records one at a time as they are being discovered (CSV‑110)”*.  
The test creates a fresh `CSVParser` for each line of input, verifies that the parser correctly reports a **single** record (record number = 1) and that the line‑number counters are reset for every new parse. It also checks that the parsed values match the expected data.

```java
/**
 * Tests reusing a parser to process new string records one at a time as they are being discovered.
 * See CSV‑110.
 *
 * @throws IOException if an I/O error occurs while parsing
 */
@Test
public void testGetOneLineOneParser() throws IOException {
    // -----------------------------------------------------------------
    // 1. Prepare a small CSV source that contains three independent lines.
    // -----------------------------------------------------------------
    final String[] csvLines = {
            "a,b,c",          // line 1
            "1,2,3",          // line 2
            "foo,bar,baz"     // line 3
    };

    // Expected values for each line – the same order as csvLines.
    final String[][] expected = {
            {"a", "b", "c"},
            {"1", "2", "3"},
            {"foo", "bar", "baz"}
    };

    // -----------------------------------------------------------------
    // 2. Iterate over the lines, creating a *new* CSVParser for each line.
    //    The parser is used only once (one record) and then closed.
    // -----------------------------------------------------------------
    for (int i = 0; i < csvLines.length; i++) {
        // Create a parser that reads only the current line.
        CSVParser parser = CSVParser.parse(csvLines[i], CSVFormat.DEFAULT);

        // The parser must contain exactly one record.
        Iterator<CSVRecord> it = parser.iterator();
        assertTrue("Parser for line " + (i + 1) + " should contain a record", it.hasNext());

        CSVRecord record = it.next();

        // -----------------------------------------------------------------
        // 3. Verify the parsed values.
        // -----------------------------------------------------------------
        String[] expectedValues = expected[i];
        assertEquals("Number of columns for line " + (i + 1), expectedValues.length, record.size());
        for (int col = 0; col < expectedValues.length; col++) {
            assertEquals("Mismatch at line " + (i + 1) + ", column " + (col + 1),
                    expectedValues[col], record.get(col));
        }

        // -----------------------------------------------------------------
        // 4. Verify that the parser’s counters are reset for each new parse.
        // -----------------------------------------------------------------
        // Because each parser only sees a single record, the record number must be 1.
        assertEquals("Record number should be 1 for line " + (i + 1), 1L, parser.getRecordNumber());

        // The line number reported by the parser is also 1 (the first line of the
        // supplied input string).  CSVParser counts *physical* lines, not logical
        // CSV records, so for a single‑line input the value is 1.
        assertEquals("Current line number should be 1 for line " + (i + 1), 1L, parser.getCurrentLineNumber());

        // No more records must be present.
        assertFalse("Parser for line " + (i + 1) + " should contain only one record", it.hasNext());

        // Clean up.
        parser.close();
    }
}
```

### What the test validates

1. **Parser recreation per line** – a fresh `CSVParser` is instantiated for each CSV line, mimicking the “one‑line‑at‑a‑time” usage pattern described in CSV‑110.  
2. **Correct parsing of values** – each record’s fields are compared against the expected values.  
3. **Reset of internal counters** – after each new parser creation the record number and current line number are both `1`, confirming that the parser does **not** retain state from a previous parse.  
4. **Resource handling** – the parser is explicitly closed after each iteration to ensure no resource leaks.
