**Explanation**

`JsonWriter` has a *lenient* mode that permits writing JSON that is not strictly compliant with the JSON specification (e.g., allowing `NaN` or infinite numbers).  
The original implementation of `value(double)` always throws an `IllegalArgumentException` when the supplied double is `NaN` or infinite, **ignoring the `lenient` flag**. This makes the `setLenient(true)` API ineffective for numeric values and is a regression compared with the reference implementation of Gson’s `JsonWriter`.

The fix is straightforward:

1. Guard the validation with the `lenient` flag – only reject non‑finite numbers when the writer is **not** lenient.
2. Keep the rest of the logic unchanged (write any pending name, emit the value, and return `this`).

**Why this fixes the bug**

* **No side‑effects** – The surrounding calls (`writeDeferredName()` and `beforeValue()`) remain in the same order, preserving existing formatting and state‑management logic.

With this change the `JsonWriter` works correctly in both strict and lenient configurations.
