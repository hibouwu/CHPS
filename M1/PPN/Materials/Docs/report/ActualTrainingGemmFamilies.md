# Actual Training GEMM Shape Families

## Tracing Method

Shape tracing is implemented in `src/gemm/matmul_dispatch.cpp` via `MatmulShapeTracer`.
It is off by default and is activated with two environment variables:

```
MATMUL_TRACE_SHAPES=1                              # enable tracing
MATMUL_TRACE_SHAPES_FILE=<path>/matmul_shapes.csv  # output file (default: matmul_shapes.csv)
```

The tracer records every call to `Matrix::matmul_into()` with columns: `M,K,N,transA,transB,impl`.
Thread safety is ensured with `std::mutex`; the header row is written lazily on the first call.

Tracing does not modify GEMM math, does not affect correctness, and adds zero overhead when disabled.

## Identified GEMM Families

### conv_fwd_medium_k_nn (transB, K≤200, N≤32)

Forward pass of a depthwise-style conv layer after im2col.
Characteristic: large M (output spatial positions × batch), moderate K (kernel × channels), small N (output channels).

Representative: `M=3200, K=150, N=16` — output positions × batch × kernel patches.

### conv_dx_extremely_skinny_k_nn (no trans, K≤32, M≥500)

Input gradient of a conv layer: `dX = dOut @ W`.
After im2col layout, K equals the number of output feature maps (very small), M is large.

Representative: `M=3200, K=16, N=150`.

### conv_dw_transposed_very_skinny_m_nn (transA, M≤32, K≥100)

Weight gradient of a conv layer: `dW = X^T @ dOut`.
M is the number of output channels (small), K is large (spatial × batch).

Representatives: `M=16, K=3200, N=150`; `M=6, K=25088, N=25`.

> **Custom GotoBLAS caveat:** the custom AVX2/AVX-512 implementations in this project only
> handle non-transposed GEMMs (`!transA && !transB`). Transposed calls fall back to the scalar
> triple loop in `matmul_dispatch.cpp`. The benchmark binary (`test_benchmark_large`) always
> runs non-transposed. When benchmarking `cnn_conv2_dw_b32 (16×3200×150)` you are measuring
> the non-transposed GEMM throughput for those dimensions — the production dW path uses BLAS
> regardless of which custom impl is selected.

### conv_fwd_very_skinny_k_small_n_nn (transB, K≤50, N≤32)

Forward pass of Conv1 on full MNIST images.
Extreme case: M=25088 (28×28×32 positions in a batch), K=25 (5×5 kernel), N=6 channels.
Very large M, very small K and N.

### fc_forward_mainstream_nn (various)

Standard dense forward pass.
`M = batch_size`, `K = input_features`, `N = output_features`.

Representatives: `(32,784,128)`, `(32,400,120)`.

### transposed_weight_grad_nn (transA)

Weight gradient of a dense layer: `dW = X^T @ dOut`.
`M = input_features`, `K = batch_size`, `N = output_features`.

> Same caveat as `conv_dw_transposed_very_skinny_m_nn`: custom implementations use BLAS for this path.

## Recommended Benchmark Workloads (training-trace set)

These are the workloads added to `run_fixed_strong_scaling_comparison.py` under
`--workload-set training-trace`. All shapes are benchmarked as non-transposed `(M×K)@(K×N)`
since the custom GotoBLAS kernels only implement the non-transposed path.

| WorkloadId | M | K | N | Source | FLOPs% |
| --- | --- | --- | --- | --- | --- |
| cnn_conv2_fwd_b32 | 3200 | 150 | 16 | CNN trace | 23.3% |
| cnn_conv2_dx_b32 | 3200 | 16 | 150 | CNN trace | 20.0% |
| cnn_conv2_dw_b32 | 16 | 3200 | 150 | CNN trace | 20.0% |
| cnn_conv1_fwd_b32 | 25088 | 25 | 6 | CNN trace | 11.4% |
| cnn_conv1_dw_b32 | 6 | 25088 | 25 | CNN trace | 9.8% |
| cnn_fc1_b32 | 32 | 400 | 120 | CNN trace | 4.7% |
| mlp_fc1_b32 | 32 | 784 | 128 | MLP trace | 36.4% (MLP) |

Note that `cnn_conv1_dw_b32 (6×25088×25)` and `cnn_conv2_dw_b32 (16×3200×150)` have very small M.
Parallelisation over M is limited; thread-scaling behaviour for these shapes is expected to differ
from larger-M workloads.

## Impact on Existing Workload Sets

The existing `MINIMAL_WORKLOADS` and `FULL_WORKLOADS` in the strong-scaling runner already contain
`cnn_conv2_dX_b32 (3200,16,150)` and `mlp_fc1_b32 (32,784,128)`.

Shapes that were absent before this analysis:
- `cnn_conv2_fwd_b32 (3200,150,16)` — the highest-FLOPs single shape in CNN training
- `cnn_conv2_dw_b32 (16,3200,150)` — Conv2 weight gradient
- `cnn_conv1_fwd_b32 (25088,25,6)` — Conv1 forward, extreme large-M regime
- `cnn_conv1_dw_b32 (6,25088,25)` — Conv1 weight gradient
